## 摘要
长上下文大语言模型（LLM）要求在低延迟下进行准确推理，然而随着上下文的增长，解码过程主要受到 KV 缓存的限制。先前的剪枝方法在很大程度上是上下文无关的：它们的令牌选择忽略了逐步相关性和局部语义，从而损害了生成质量。此外，它们不规则的访问和选择开销仅能带来有限的实际加速。为了解决这些问题，我们提出了 CHESS，一种算法-系统协同设计的 KV 缓存管理系统。在算法上，CHESS 引入了一种上下文感知的分层选择策略，为当前的解码动态重构连贯的上下文。在系统上，粗粒度选择消除了昂贵的数据移动，将理论上的稀疏性充分转化为实际加速。广泛的评估表明，CHESS 仅使用 1% 的 KV 缓存即可超越全量 KV 的质量，提供低延迟的稳定推理，吞吐量提升高达 4.56 倍，并持续优于其他强基准方法。代码可在 https://anonymous.4open.science/r/CHESS/ 获取。

## Abstract
Long-context LLMs demand accurate inference at low latency, yet decoding becomes primarily constrained by KV cache as context grows. Prior pruning methods are largely context-agnostic: their token selection ignores step-wise relevance and local semantics, which undermines quality. Moreover, their irregular accesses and selection overheads yield only limited wall-clock speedups. To address this, we propose \textbf{CHESS}, an \textit{algorithm-system co-design} KV-cache management system. Algorithmically, CHESS introduces a context-aware, hierarchical selection policy that dynamically reconstructs a coherent context for the current decoding. System-wise, coarse granularity selection eliminates expensive data movement, fully realizing practical acceleration from theoretical sparsity. Extensive evaluations demonstrate that CHESS surpasses Full-KV quality using only \textbf{1\%} of the KV cache, delivers low-latency stable inference with up to \textbf{4.56$\times$} higher throughput, and consistently outperforms other strong baselines. 随着大语言模型（LLM）处理的上下文长度不断增加，推理过程面临严重的**内存墙（Memory Wall）**和**计算墙（Compute Wall）**挑战。KV 缓存（KV Cache）的线性增长导致 I/O 带宽成为瓶颈，且注意力计算开销激增。
*   **现有方法的缺陷**：
    *   **上下文无关（Context-agnostic）**：如 SnapKV 等方法在预填充阶段固定保留 Token，忽略了解码过程中语义重心的动态偏移。
    *   **系统开销大**：Token 粒度的剪枝导致内存访问不连续，且维护注意力分数（Attention Scores）会引入额外的 I/O 负担，难以在实际硬件上实现理论加速。
*   **研究目标**：设计一种算法与系统协同的方案，既能动态感知当前生成的语义需求，又能利用硬件友好的块状管理实现真正的推理加速。

#### 2. 论文提出的方法论：CHESS
CHESS 采用**算法-系统协同设计**，核心思想是根据当前生成的上下文动态重构 KV 缓存。
*   **分层语义表示**：将 KV 缓存组织为“网格（Grid）→ 块（Chunk）→ 页（Page）”的三级层次结构。通过对 Key 状态进行均值池化（Mean-pooling）生成每一层的语义向量。
*   **上下文感知选择机制**：
    *   **查询锚点（Query Anchor）**：利用最近生成的 Token 的 Key 状态构建当前语义锚点。
    *   **Key-Key 语义亲和力**：计算锚点与历史各层级向量的点积相似度，采用自上而下（网格到页）的过滤策略，仅保留语义最相关的页。
*   **质量感知回溯（Quality-Aware Backtracking）**：引入不确定性指标（熵 Entropy 和 变分熵 Varentropy）。当生成质量下降（不确定性超过阈值）时，触发上下文重构，找回被剪枝的信息。
*   **系统实现优化**：
    *   **零拷贝推理引擎**：基于 PagedAttention，通过操纵逻辑页索引而非物理移动数据来实现 KV 缓存管理。
    *   **高性能算子**：利用向量化 GEMM 优化相似度计算，并将整个流程封装在 CUDA Graphs 中以减少内核启动开销。
