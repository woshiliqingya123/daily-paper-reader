## 摘要
长期运行的智能体任务（如深度研究）需要对分布在多个网页和文档中的信息进行多跳推理。在这些任务中，大语言模型（LLM）的上下文主要由来自外部检索的 token 占据，导致内存占用迅速增长并限制了解码性能。虽然目前已存在几种针对长上下文输入的 KV 缓存压缩技术，但我们发现现有的启发式方法无法有效支持多步推理模型。为了应对这一挑战，我们提出了 SideQuest——一种利用大推理模型（LRM）自身通过推理上下文中 token 的有用性来进行 KV 缓存压缩的新颖方法。为了防止与该管理过程相关的 token 污染模型的内存，我们将 KV 缓存压缩构建为与主推理任务并行执行的辅助任务。我们的评估结果显示，使用仅 215 个样本训练的模型，SideQuest 在智能体任务上的峰值 token 使用量减少了高达 65%，且准确率下降极小，性能优于基于启发式的 KV 缓存压缩技术。

## Abstract
Long-running agentic tasks, such as deep research, require multi-hop reasoning over information distributed across multiple webpages and documents. In such tasks, the LLM context is dominated by tokens from external retrieval, causing memory usage to grow rapidly and limiting decode performance. While several KV cache compression techniques exist for long-context inputs, we find that existing heuristics fail to support multi-step reasoning models effectively. We address this challenge with SideQuest -- a novel approach that leverages the Large Reasoning Model (LRM) itself to perform KV cache compression by reasoning about the usefulness of tokens in its context. To prevent the tokens associated with this management process from polluting the model's memory, we frame KV cache compression as an auxiliary task executed in parallel to the main reasoning task. Our evaluations, using a model trained with just 215 samples, show that SideQuest reduces peak token usage by up to 65% on agentic tasks with minimal degradation in accuracy, outperforming heuristic-based KV cache compression techniques.

#### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）向自主智能体（Agents）演进，长程、多跳推理任务（如深度研究、自动化软件工程）变得普遍。这类任务的上下文通常被大量的外部检索内容（工具调用结果）占据，导致 **KV 缓存（KV Cache）** 呈线性增长。
*   **瓶颈**：巨大的 KV 缓存不仅消耗 GPU 显存（限制批处理大小），还导致注意力机制受限于内存带宽（增加推理延迟）。
*   **现有缺陷**：现有的 KV 缓存压缩技术（如 H2O, SnapKV）多依赖于固定的启发式规则（如保留高频注意力 Token）。但在智能体任务中，Token 的重要性是动态且非单调的——早期看似无关的信息可能在十个步骤后变得至关重要。启发式方法往往会误删关键信息，导致推理失败。

#### 2. 方法论：核心思想与关键技术
SideQuest 的核心思想是**让大推理模型（LRM）通过语义理解自行管理内存**，即执行“内存垃圾回收”。

*   **并行辅助线程（Parallel Auxiliary Thread）**：
    *   系统定期派生一个与主推理线程共享上下文的辅助线程。
    *   辅助线程分析当前任务状态，识别哪些已有的工具调用结果（以 Cursor 游标标识）已不再需要。
    *   输出结构化指令（如 `{del_cursors: [0]}`）来精确清理 KV 缓存。
    *   **优势**：这种并行架构避免了管理相关的 Token 污染主线程的上下文空间，且不增加主任务延迟。
*   **模型引导与微调**：
    *   通过特定的触发词（如 `** Memory management mode **`）切换模型模式。
    *   **事后分析数据生成（Hindsight Annotation）**：利用模型在正确推理轨迹上的表现，回溯识别哪些 Token 在后续步骤中从未被引用，从而自动生成训练标签。
    *   **联合优化**：使用交叉熵损失训练管理能力，同时使用逻辑蒸馏（Logit Distillation）确保模型不丧失原始的推理能力。
