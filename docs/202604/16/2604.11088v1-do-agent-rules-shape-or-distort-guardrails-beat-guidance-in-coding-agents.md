## 摘要
开发者越来越多地通过自然语言指令文件（如 CLAUDE.md、.cursorrules）来引导 AI 编程智能体，但目前尚无受控研究衡量这些规则是否真的提升了智能体性能，或者哪些属性使规则有益。我们从 GitHub 抓取了 679 个此类文件（共 25,532 条规则），并进行了首次大规模实证评估，在 SWE-bench Verified 基准测试上使用最先进的编程智能体运行了 5,000 多次。研究发现，规则将性能提升了 7-14 个百分点，但随机规则的效果与专家策划的规则相当——这表明规则是通过上下文启动（context priming）而非具体指令发挥作用的。负面约束（如“不要重构无关代码”）是唯一在单独使用时有益的规则类型，而正面指令（如“遵循代码风格”）反而会产生负面影响——我们通过基于势能的奖励塑造（PBRS）视角分析了这一模式。此外，单条规则在孤立状态下大多有害，但集体使用时却有帮助，且在规则数量达到 50 条之前性能没有下降。这些发现揭示了一个隐藏的可靠性风险——初衷良好的规则往往会降低智能体性能——并为安全的智能体配置提供了一个明确的原则：约束智能体不得做的事情，而不是规定它们应该做的事情。

## Abstract
Developers increasingly guide AI coding agents through natural language instruction files (e.g., CLAUDE.md, .cursorrules), yet no controlled study has measured whether these rules actually improve agent performance or which properties make a rule beneficial. We scrape 679 such files (25,532 rules) from GitHub and conduct the first large-scale empirical evaluation, running over 5,000 agent runs with a state-of-the-art coding agent on SWE-bench Verified. Rules improve performance by 7--14 percentage points, but random rules help as much as expert-curated ones -- suggesting rules work through context priming rather than specific instruction. Negative constraints ("do not refactor unrelated code") are the only individually beneficial rule type, while positive directives ("follow code style") actively hurt -- a pattern we analyze through the lens of potential-based reward shaping (PBRS). Moreover, individual rules are mostly harmful in isolation yet collectively helpful, with no degradation up to 50 rules. These findings expose a hidden reliability risk -- well-intentioned rules routinely degrade agent performance -- and provide a clear principle for safe agent configuration: constrain what agents must not do, rather than prescribing what they should.

### 1. 核心问题与整体含义
*   **研究动机**：开发者习惯编写自然语言指令来引导 AI 智能体（如“运行测试后再提交”、“不要修改无关文件”），但这些规则是否真的有效、哪些规则有效、其背后的作用机制是什么，此前一直缺乏受控的实证研究。
*   **核心问题**：智能体规则是“塑造”（Shape，即优化行为）还是“扭曲”（Distort，即干扰性能）？
*   **整体含义**：研究揭示了规则对智能体性能的影响并非完全取决于语义内容，而是存在显著的“启动效应”和“负向约束优于正向引导”的规律。

### 2. 方法论
*   **核心思想**：通过大规模抓取真实世界的规则文件，结合强化学习中的**基于势能的奖励塑造（PBRS）**理论，对规则进行分类和受控实验。
*   **关键技术细节**：
    *   **数据构建**：从 GitHub 抓取 679 个规则文件，提取 25,532 条规则，并将其分为六大类：项目特定、行为/人格、工具/流程、代码风格、架构、安全。
    *   **理论框架**：引入 PBRS 视角，将规则分为“状态相关”（如流程指令，类似于有效的奖励塑造）和“状态无关”（如风格指令，可能导致奖励扭曲）。
    *   **规则注入**：在智能体启动前，通过在工作目录放置 `CLAUDE.md` 文件，让智能体自动读取并遵循。
    *   **任务筛选**：从 500 个任务中筛选出 58 个“判别性任务”（基准成功率在 30%-70% 之间），以放大规则带来的性能差异信号。

### 3. 实验设计
*   **数据集/场景**：使用 **SWE-bench Verified**（包含 500 个真实的 GitHub 问题）。
*   **智能体（Agent）**：使用最先进的 **Claude Code (搭载 Claude 4.6 Opus)**。
*   **对比实验设计**：
    *   **来源对比**：对比专家策划规则、随机规则、错误领域规则、打乱语序规则等。
    *   **数量对比**：测试 0 到 50 条规则对性能的影响。
    *   **类型对比**：对比流程类、安全类、风格类等不同类别的效果。
    *   **消融实验**：对 18 条核心规则进行逐一剔除，观察性能变化。

### 5. 实验数量与充分性
*   **实验规模**：总计运行 5,000 多次，涵盖了 8 种规则来源、19 种规则数量配置、5 种规则类型以及针对 18 条规则的详细消融实验。
*   **充分性与客观性**：

    *   通过引入“随机规则”和“打乱语序规则”作为对照组，有效地排除了语义干扰，证明了实验的客观性。

### 6. 主要结论与发现
*   **上下文启动效应（Context Priming）**：规则能提升 7-14% 的性能，但**具体内容并不重要**。随机规则、错误领域规则甚至语序打乱的规则都能带来类似的提升。这表明规则的存在本身激活了智能体更谨慎的解决问题模式。
*   **护栏优于引导（Guardrails Beat Guidance）**：
    *   **负向约束（禁止做什么）**是唯一能显著提升性能的规则类型（如“不要重构无关代码”）。
    *   **正向指令（应该做什么）**往往会损害性能（如“遵循代码风格”），因为它们增加了智能体的动作空间，分散了注意力。
*   **集成韧性（Ensemble Resilience）**：单条规则往往有害（18 条规则中有 14 条在单独使用时会破坏原本能解决的任务），但集体使用时却能互相抵消负面影响并产生正面效果。
*   **数量无害性**：规则数量增加到 50 条时，性能并未出现下降。

### 7. 优点
*   **实证性强**：填补了 AI 编程智能体配置领域的研究空白，提供了大量真实运行数据。
*   **视角独特**：借用强化学习的 PBRS 理论来解释自然语言指令的效果，具有跨学科的启发性。
*   **结论实用**：为开发者提供了明确的建议——多写“不要做”，少写“要做”。

### 8. 不足与局限
*   **模型局限**：实验仅基于 Claude 4.6 Opus，较弱的模型可能对规则内容的敏感度不同。
*   **任务局限**：主要集中在 Python 语言的 Bug 修复，可能无法完全推广到其他编程语言或新功能开发场景。
*   **筛选偏差**：为了获得信号，实验主要在“判别性任务”上运行，虽然作者验证了规则不会让“必过任务”变差，但样本覆盖仍有选择性。
