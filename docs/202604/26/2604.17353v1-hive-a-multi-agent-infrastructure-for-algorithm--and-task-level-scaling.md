## 摘要
大语言模型正越来越多地被部署为复杂的智能体系统，并随任务复杂度的增加而扩展。尽管先前的工作已广泛探索了模型级和系统级扩展，但算法级和任务级扩展在很大程度上仍未得到解决，这限制了智能体系统的全部潜力。在算法层面，分配额外的推理时计算资源可以增强工作流能力，但会引入跨路径冗余：即多个推理分支之间存在重叠计算。在任务层面，复杂任务可以分解为子问题并委派给多个智能体，以提高可扩展性和并行性。然而，现有基础设施的调度机制无法感知多个智能体的存在，从而错失了优化资源分配的机会。我们提出了 Hive，这是一种支持算法级和任务级扩展的多智能体基础设施。Hive 具有一个描述前端，用于捕获每个智能体的行为并支持测试时扩展算法。利用这一规范，我们的后端引入了两个关键机制：Logits Cache（Logits 缓存），通过在冗余采样路径中重用中间 Logits 来减轻算法层面的跨路径冗余；以及 Agent-Aware Scheduling（智能体感知调度），根据任务层面的智能体贡献高效分配计算和 KV 缓存资源。实验表明，Logits Cache 在重采样方面实现了平均 1.11x-1.76x 的加速，而 Agent-Aware Scheduling 将热点缺失率降低了 33%-51%。

## Abstract
Large language models are increasingly deployed as complex agentic systems that scale with task complexity. While prior work has extensively explored model- and system-level scaling, algorithm- and task-level scaling remain largely unaddressed, constraining the full potential of agentic systems. At the algorithm level, allocating additional inference-time computation can enhance workflow capacity but introduces cross-path redundancy: overlapping computations across multiple reasoning branches. At the task level, complex tasks can be decomposed into subproblems and delegated across multiple agents for improved scalability and parallelism. However, existing infrastructures' scheduling is unaware of the existence of multiple agents, missing opportunities to optimize resource allocation.   We propose Hive, a multi-agent infrastructure that enables algorithm- and task-level scaling. Hive features a description frontend that captures per-agent behavior and supports test-time scaling algorithms. Leveraging this specification, our backend introduces two key mechanisms: Logits Cache that reuses intermediate logits across redundant sampling paths to mitigate cross-path redundancy at the algorithm level, and Agent-Aware Scheduling that efficiently allocates compute and KV-cache resources according to agent contributions at the task level. Experiments show that Logits Cache achieves an average speedup of $1.11\times$-$1.76\times$ for re-sampling, and Agent-Aware Scheduling reduces the hotspot miss rate by $33\%$-$51\%$.

### 论文总结：Hive —— 算法与任务级扩展的多智能体基础设施

#### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）从简单的问答引擎转向复杂的智能体系统，推理过程变得更加状态化且具有结构性。论文指出，现有的推理系统（如 vLLM、SGLang）主要关注**模型级**（如量化）和**系统级**（如并行化）的扩展，但在以下两个维度存在瓶颈：
*   **算法级扩展（Algorithm-Level Scaling）：** 诸如“思维树”（Tree-of-Thoughts）等测试时扩展（Test-Time Scaling）算法会产生大量重采样请求。这些请求虽然前缀相同，但在解码阶段仍存在大量重复的 Logits 计算，即“跨路径冗余”。
*   **任务级扩展（Task-Level Scaling）：** 多智能体系统（MAS）中不同角色的智能体（如决策者、代码修复者、搜索者）具有极高的负载异构性。现有的调度器无法感知智能体身份，导致关键智能体的 KV 缓存被频繁驱逐，降低了整体效率。

#### 2. 方法论：核心思想与关键技术
Hive 提出了一个全栈式架构，包含前端描述层和后端优化层：
*   **前端描述与异步运行时：** 采用类似 Python 协程的抽象，将智能体行为编译为流图（Flow Graph），并引入“监督者”（Supervisor）机制，使智能体逻辑与测试时扩展算法（如 ToT）解耦。
*   **Logits Cache（算法级优化）：** 
    *   **核心思想：** 不仅缓存 KV 状态，还缓存解码阶段生成的 Logits 分布。
    *   **技术细节：** 提供两种策略：**逐步采样（Step-wise）**在采样分叉前完全复用 Logits；**热点采样（Hotspot）**通过计算 Logits 的熵和 Top-1 概率识别“不稳定”位置，仅在关键点重采样，其余位置直接复用，从而大幅减少前向计算。
*   **Agent-Aware Scheduling（任务级优化）：**
    *   **核心思想：** 基于博弈论中的 **Shapley 值** 建模智能体贡献度。
    *   **技术细节：** 贡献度由“内在效用”（活跃度、工作量、缓存效率、并发度）和“协作效用”（与其他智能体共享缓存的频率）共同决定。调度器根据贡献度得分动态调整 GPU 内存中 KV 缓存的驱逐优先级，优先保留高贡献智能体的状态。

#### 3. 实验设计
*   **场景与数据集：**
    *   **算法级：** 使用 24 点游戏（24-Game）数据集，模拟思维树（ToT）的重采样过程。
    *   **任务级：** 基于硬件验证多智能体框架 R3A，模拟包含 Decision、Patcher、Viewer、Summary、Searcher 五个角色的复杂工作流。
*   **Benchmark 与对比方法：**
    *   **基准：** 以 SGLang 为基础实现。
    *   **对比：** 算法级对比“无 Logits 缓存”的常规推理；任务级对比传统的 **LRU（最近最少使用）** 驱逐策略。

*   **硬件：** 1 台服务器，配备 **8 张 NVIDIA A100 GPU**（实验主要在单卡上运行以验证效率），Intel Xeon Gold 6348 CPU。

*   **模型：** 主要使用 **Qwen3-8B** 作为基础模型进行评估。

#### 5. 实验数量与充分性
*   **实验规模：** 针对 Logits Cache 进行了 100 个 ToT 实例的测试，涵盖了从 0.1 到 0.9 的不同温度设置；针对调度器进行了 21 轮多智能体协作模拟。
*   **充分性：** 实验涵盖了性能加速比、Logits 命中率、KV 缓存命中率、智能体优先级动态演变等多个维度。

#### 6. 主要结论与发现
*   **算法加速：** Logits Cache 在逐步采样下实现平均 **1.11x** 加速，在热点采样下实现 **1.76x** 加速。
*   **缓存优化：** 智能体感知调度器将热点缺失率（Hotspot Miss Rate）降低了 **33%–51%**，并减少了约 **19.2%–30.2%** 的 KV Token 驱逐量。
*   **异构性验证：** 实验证实了多智能体系统中存在显著的负载倾斜（70% 的消耗集中在少数智能体），证明了感知智能体身份进行调度的必要性。

#### 7. 优点
*   **创新视角：** 首次将 Logits 级别的复用引入测试时扩展算法的系统优化中。
*   **理论支撑：** 引入 Shapley 值量化智能体贡献，使资源分配具有数学上的公平性和合理性。
*   **全栈设计：** 提供了从前端编程模型到后端执行引擎的完整解决方案，降低了开发复杂 MAS 的门槛。

#### 8. 不足与局限
*   **模型规模限制：** 实验主要基于 8B 参数模型，虽然理论上模型越大收益越高，但缺乏在超大规模模型（如 70B+）上的实测数据。
*   **领域局限性：** 核心案例和实验高度依赖硬件验证（RTL Repair）场景，对于创意写作、通用搜索等其他 MAS 场景的普适性有待进一步验证。
*   **Logits 存储开销：** 虽然 Logits 存储在主机内存中，但对于超大词表模型，Logits 缓存的内存占用和传输带宽可能成为新的瓶颈。
