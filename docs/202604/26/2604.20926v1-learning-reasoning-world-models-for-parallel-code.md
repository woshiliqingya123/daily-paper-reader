## 摘要
大语言模型在串行代码生成方面表现出卓越的能力，但在训练数据相对稀缺的并行代码方面仍面临挑战。一种常见的补救措施是使用与外部工具交互的代码智能体，但工具调用可能成本高昂，且有时在处理部分编写的代码等情况下并不切实际。我们提出了并行代码世界模型（PCWMs），这是一种旨在直接从并行源代码预测工具执行结果的推理大语言模型。为了训练 PCWMs，我们设计了一种新颖的探索与数据生成流水线，该流水线在多个领域采样多样的并行编程问题及其候选实现，随后通过工具执行这些代码以记录数据竞争和性能分析数据。基于这些数据，我们合成了事后推理轨迹，将源代码与观察到的工具结果建立因果联系。在所得数据上进行微调带来了显著的性能提升：一个 7B 参数的世界模型在竞争结果预测中的准确率从 64.3% 提高到 72.8%，而一个 8B 参数的模型在性能分析任务中的准确率从 49.3% 提高到 58.6%。此外，当要求开源权重模型修复数据竞争时，相比于自我反馈，使用我们的 7B 参数世界模型提供的反馈将竞争修复率提高了 2.7%-9.1%，而使用 14B 参数世界模型则提高了 6.1%-11.1%。我们的研究结果表明，推理模型有潜力在并行代码智能体中作为外部工具调用的实用替代方案。

## Abstract
Large language models have shown remarkable ability in serial code generation, but they still struggle with parallel code for which training data is comparatively scarce. A common remedy is to use coding agents that interact with external tools, but tool calls can be costly and sometimes impractical, e.g., for partially written code. We propose Parallel-Code World Models (PCWMs), reasoning LLMs that aim to predict tool outcomes directly from parallel source code. To train PCWMs, we design a novel exploration and data generation pipeline that samples diverse parallel-coding problems and candidate implementations across multiple domains, then executes them via tools to record data races and performance profiles. From these, we synthesize hindsight reasoning traces that causally connect source code to observed tool outcomes. Fine-tuning on the resulting data yields noticeable gains, with a 7B-parameter world model improving from 64.3% to 72.8% accuracy in race-outcome prediction, while an 8B-parameter model improves in a performance profiling task from 49.3% to 58.6% accuracy. Furthermore, when open-weight models were tasked with fixing data races, world-model feedback improved their race-fixing rates relative to self-feedback by 2.7%-9.1% using our 7B-parameter world model and by 6.1%-11.1% using our 14B-parameter world model. Our results suggest that reasoning models have the potential to serve as practical substitutes for external tool calls in parallel-coding agents.

    *   **目标**：开发“并行代码世界模型”（PCWMs），使其能够像人类专家一样，直接通过阅读源代码推理出工具的运行结果（如是否存在数据竞争、性能瓶颈在哪里）。

### 2. 方法论
*   **核心思想**：通过“事后推理轨迹”（Hindsight Reasoning Traces）训练模型。模型不仅要预测工具的输出，还要生成一段解释代码与结果之间因果关系的思维链（CoT）。
*   **关键技术细节**：
    1.  **自动化数据生成流水线**：
        *   **问题生成**：使用 GPT-4o 在 10 个领域生成并行编程问题及测试框架（Harness）。
        *   **多样化实现**：利用多种开源模型（Llama-3.3-70B, Phi-4 等）生成针对同一问题的多种并行实现（包含正确和错误的）。
        *   **工具执行**：运行代码并记录 **ThreadSanitizer**（检测数据竞争）和 **Caliper**（性能分析，计算工作百分比）的真实输出。
    2.  **事后思维链（Hindsight CoT）合成**：
        *   使用强推理模型（如 QwQ-32B）作为教师模型。
        *   **关键点**：在合成推理轨迹时，将工具的真实结果提供给教师模型，要求其“反向推理”出从代码到该结果的逻辑路径，从而确保推理过程与事实一致。
    3.  **监督微调（SFT）**：将代码作为输入，[推理轨迹 + 工具结果] 作为目标序列进行微调。

### 6. 主要结论与发现
*   **推理至关重要**：直接预测结果效果较差，而通过 CoT 引导模型“思考”能显著提升准确率（7B 模型准确率从 64.3% 提升至 72.8%）。
*   **事后引导的必要性**：如果不提供真实结果给教师模型生成 CoT，训练出的世界模型容易产生幻觉，甚至导致性能崩溃。
*   **反馈有效性**：在修复并行代码错误时，PCWM 提供的反馈优于模型自我反馈，甚至在某些情况下优于工具的原始输出（因为 PCWM 提供了额外的因果解释）。
*   **规模效应**：大模型（32B）能用更短的推理轨迹达到更高的准确率，表现出更高的推理效率。

### 7. 优点
*   **创新性应用**：首次将“世界模型”的概念深入引入到高性能计算（HPC）并行代码分析领域。
*   **解决冷启动问题**：通过自动化的流水线解决了并行代码推理数据稀缺的问题。
*   **实用性强**：PCWM 可以处理部分代码，且推理速度远快于配置和运行真实的 HPC 性能分析工具。

### 8. 不足与局限
*   **编程模型局限**：目前仅限于 **OpenMP**，尚未扩展到 MPI、CUDA 或其他并行框架。
*   **性能预测精度**：在性能分析任务中，当两个代码版本的效率非常接近时（Near-tie cases），模型的排序准确率会显著下降。
*   **商业模型瓶颈**：实验发现 GPT-4o 等商业模型对 PCWM 反馈的敏感度较低，提升不如开源模型明显。
*   **环境依赖**：性能分析（Caliper）结果受硬件环境影响较大，模型在跨平台泛化上的表现仍需进一步验证。
