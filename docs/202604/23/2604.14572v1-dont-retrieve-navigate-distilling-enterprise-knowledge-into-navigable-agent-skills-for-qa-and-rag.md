## 摘要
检索增强生成（RAG）将大语言模型（LLM）的响应建立在外部证据之上，但将模型视为搜索结果的被动消费者：模型无法感知语料库的组织结构，也无法获知尚未检索到的内容，这限制了其回溯或整合分散证据的能力。我们提出了 Corpus2Skill，它在离线阶段将文档语料库蒸馏为层级化的技能目录，并允许 LLM 智能体在推理阶段对其进行导航。该编译流水线迭代地对文档进行聚类，在每个层级生成由 LLM 编写的摘要，并将结果实例化为一棵由可导航技能文件组成的树。在推理阶段，智能体可以获得语料库的全景视图，通过逐渐细化的摘要深入探索主题分支，并根据 ID 检索完整文档。由于层级结构是显式可见的，智能体可以推理寻找路径、从无效路径回溯，并跨分支整合证据。在企业级客服 RAG 基准测试 WixQA 上，Corpus2Skill 在所有质量指标上均优于稠密检索、RAPTOR 以及智能体化 RAG 基准模型。

## Abstract
Retrieval-Augmented Generation (RAG) grounds LLM responses in external evidence but treats the model as a passive consumer of search results: it never sees how the corpus is organized or what it has not yet retrieved, limiting its ability to backtrack or combine scattered evidence. We present Corpus2Skill, which distills a document corpus into a hierarchical skill directory offline and lets an LLM agent navigate it at serve time. The compilation pipeline iteratively clusters documents, generates LLM-written summaries at each level, and materializes the result as a tree of navigable skill files. At serve time, the agent receives a bird's-eye view of the corpus, drills into topic branches via progressively finer summaries, and retrieves full documents by ID. Because the hierarchy is explicitly visible, the agent can reason about where to look, backtrack from unproductive paths, and combine evidence across branches. On WixQA, an enterprise customer-support benchmark for RAG, Corpus2Skill outperforms dense retrieval, RAPTOR, and agentic RAG baselines across all quality metrics.

*   **研究动机**：传统的检索增强生成（RAG）将大语言模型（LLM）视为搜索结果的“被动消费者”。LLM 只能看到检索到的片段（“树木”），而无法感知整个语料库的组织结构（“森林”）。这导致模型在面对复杂查询时，无法进行有效的回溯、无法识别缺失的信息，也难以整合分散在不同主题分支下的证据。
*   **核心问题**：如何让 LLM 智能体从“被动接收检索结果”转变为“主动在知识结构中导航”，从而提升在复杂企业知识库中的问答准确性？

### 2. 方法论：Corpus2Skill 框架
该框架分为两个阶段：**离线编译（Compile）**和**在线服务（Serve）**。

*   **离线编译阶段（构建导航地图）**：
    1.  **文档嵌入与聚类**：使用嵌入模型（如 Qwen3-Embedding）对文档进行向量化，通过迭代的 K-Means 算法进行自底向上的层级聚类。
    2.  **层级摘要生成**：在每个聚类层级，调用 LLM 对该簇内的文档或子簇摘要进行总结，生成描述该分支“涵盖什么主题”、“能回答什么问题”的导航摘要。
    3.  **技能实例化**：将层级结构转化为文件系统。根聚类变为“技能目录”（含 `SKILL.md`），子聚类变为“组目录”（含 `INDEX.md`），叶子节点指向具体文档 ID。
*   **在线服务阶段（智能体导航）**：
    1.  **渐进式披露（Progressive Disclosure）**：智能体初始只加载技能名称和简短描述。
    2.  **主动导航工具**：智能体使用 `code_execution` 工具浏览目录文件（读取摘要），并使用 `get_document` 工具根据 ID 获取完整文档。
    3.  **决策逻辑**：智能体像人类查阅目录一样，根据摘要判断路径相关性，决定是深入探索、回溯还是跨分支整合信息。

### 6. 主要结论与发现
*   **性能领先**：Corpus2Skill 在所有质量指标上均显著优于所有基准。Token F1 提升了 19%-27%，上下文召回率（0.652）远高于 Agentic RAG（0.481）。
*   **导航优于检索**：实验证明，给智能体一张“地图”让其主动寻找，比单纯通过向量相似度推送片段更有效，尤其是在需要跨主题整合证据时。
*   **结构鲁棒性**：即使使用较便宜的模型（Haiku），其导航表现依然稳健，说明预编译的知识结构本身提供了极强的引导作用。
*   **成本权衡**：高质量的代价是高昂的输入 Token 成本（约为 Agentic RAG 的 1.75 倍），因为导航过程中需要反复读取摘要文件。

### 7. 优点与亮点
*   **范式创新**：将“检索问题”转化为“导航问题”，充分利用了 LLM 的推理和规划能力。
*   **结构透明化**：通过 `SKILL.md` 和 `INDEX.md` 使语料库结构对模型可见，解决了 RAG 中的“盲目搜索”问题。
*   **无需向量库**：在线推理阶段仅依赖文件系统和 LLM，简化了企业级部署的后端架构。
*   **支持回溯**：智能体在发现路径错误时可以主动返回上一级目录，这是传统 RAG 难以实现的。

### 8. 不足与局限
*   **Token 成本高**：由于 Anthropic Skills API 的机制，每次调用都会累积之前的导航文件内容，导致输入 Token 消耗巨大。
*   **硬聚类限制**：每个文档被分配到唯一的路径。如果一个文档涉及多个主题（如“计费”和“订阅”），可能会因为初始路由错误而导致无法触达。
*   **静态编译**：目前不支持增量更新，文档库变动需要重新编译整个层级树。
*   **API 依赖**：高度依赖于支持“技能/工具调用”和长上下文处理能力的特定模型 API。
