## 摘要
功耗已成为 AI 推理的核心瓶颈。随着智能体 AI（agentic AI）成为一种主要的负载类型，这一问题变得愈发紧迫，然而先前的功耗管理技术几乎完全集中在单轮 LLM 服务上。我们的分析表明，智能体服务的行为模式有着本质的不同：每个请求都携带长期的上下文，并在工具交织的多轮交互中不断演进；此外，降低 GPU 频率可能会使系统进入“抖动”（thrashing）状态，此时内存压力会急剧恶化性能和能效。这些观察结果表明，智能体服务的功耗优化需要重新思考。我们提出了 KAIROS，一个用于智能体 AI 服务的上下文感知功耗优化系统。KAIROS 将智能体上下文作为一级控制信号，协同管理 GPU 频率、单实例并发量以及多实例请求放置。这使得 KAIROS 能够在存在内存余量时节省功耗，同时避免系统抖动并维持性能目标。从宏观层面看，KAIROS 以智能体粒度跟踪请求，根据上下文增长和智能体进度调整本地控制，并在不同实例间路由智能体，从而共同提升能效和内存稳定性。在多种软件和数据工程智能体任务上的评估显示，KAIROS 在满足性能目标的前提下，实现了平均 27%（最高达 39.8%）的功耗降低。

## Abstract
Power has become a central bottleneck for AI inference. This problem is becoming more urgent as agentic AI emerges as a major workload class, yet prior power-management techniques focus almost entirely on single-turn LLM serving. Our analysis shows that agentic serving behaves fundamentally differently: each request carries long-lived context that evolves across tool-interleaved turns, and lowering GPU frequency can push the system into a thrashing regime where memory pressure sharply worsens both performance and power efficiency. These observations show that power optimization for agentic serving requires rethinking.   We present KAIROS, a context-aware power optimization system for agentic AI serving. KAIROS uses agent context as a first-class control signal to jointly manage GPU frequency, per-instance concurrency, and multi-instance request placement. This enables KAIROS to save power when memory headroom exists while avoiding thrashing and preserving performance targets. At a high level, KAIROS tracks requests at agent granularity, adapts local control to context growth and agent progress, and routes agents across instances to jointly improve power efficiency and memory stability. Evaluated across diverse software and data engineering agentic tasks, KAIROS achieves an average of 27% (up to 39.8%) power reduction while meeting the performance targets.

### 1. 核心问题与研究动机
*   **核心问题**：随着智能体（Agentic AI）成为主流推理负载，其**长生命周期、动态增长的上下文（Context）**使得传统的单轮 LLM 功耗管理技术失效。
*   **研究动机**：
    *   **状态性差异**：智能体需要多轮工具交互，上下文随时间不断累积，导致内存压力动态变化。
    *   **“抖动”现象（Thrashing）**：简单降低 GPU 频率会减慢执行速度，导致上下文在内存中驻留时间变长。当累积上下文超过 GPU 显存容量时，系统被迫进行重算（Recomputation）或内存交换，反而导致功耗激增和性能崩溃。
    *   **现有技术局限**：现有的 DVFS（动态电压频率调整）主要针对无状态的单轮推理，未考虑上下文增长与内存稳定性之间的强耦合关系。

### 2. 方法论：KAIROS 系统设计
KAIROS 将**智能体上下文**作为一级控制信号，通过三个核心组件协同优化：
*   **智能体 ID 追踪器（Agent ID Tracker）**：通过轻量级包装器为每个智能体分配唯一 ID，使推理后端能够识别并追踪跨多轮交互的长周期工作流，而无需修改智能体程序。
*   **上下文感知的单实例控制器**：
    *   **频率控制**：根据当前显存占用率线性调整 GPU 频率。显存充足时降频节能；显存压力大时升频以加速任务完成并释放内存。
    *   **SLO 增强（Boosting）**：实时监测每个智能体的吞吐量，若低于预设目标（如 20 tokens/s），则强制提升至最高频率。
    *   **抖动规避（并发控制）**：设置显存安全阈值，当预测到新请求会导致内存溢出时，延迟接纳新智能体。
*   **上下文感知的全局路由器**：
    *   **负载整合**：在低负载时将请求集中到少数 GPU，让其余 GPU 进入低功耗待机状态。
    *   **负载均衡**：在高内存压力下，将请求分散到不同实例，以避免局部内存抖动。

*   **智能体框架**：使用 `mini-swe-agent` 和 `Terminus-2`。
*   **对比基准（Baselines）**：

*   **硬件环境**：使用 **NVIDIA H100 NVL** GPU（80GB 显存），配以 Intel Xeon Platinum 8592+ CPU 和 2TB DRAM。

### 5. 实验数量与充分性
*   **实验规模**：涵盖了 3 个不同领域的基准测试、2 种智能体架构、2 种不同规模的模型。

### 6. 主要结论与发现
*   **节能效果显著**：在单实例下平均降低功耗 **27%**（最高 **39.8%**）；在多实例场景下，结合路由优化可实现 **46.3%** 的功耗降低。
*   **性能保障**：KAIROS 能够精准维持 P5 吞吐量目标，而固定频率方法在同等功耗下会导致严重的 SLO 违规。
*   **内存稳定性**：证明了通过主动频率管理可以有效防止系统进入高能耗、低效率的内存抖动 regime。

### 7. 优点与亮点
*   **视角新颖**：首次识别并量化了智能体推理中“功耗-性能-内存稳定性”之间的三角冲突。
*   **指标创新**：提出了更符合智能体特性的“每智能体吞吐量”作为 SLO 衡量标准。
*   **实用性强**：ID 追踪机制无需修改现有的智能体代码或复杂的语义分析，易于在生产环境中部署。
*   **协同优化**：将底层的硬件频率控制与上层的请求路由、并发控制有机结合。

*   **架构限制**：主要针对 ReAct 类型的智能体，对于更复杂的搜索类智能体（如 LATS）或具有极高分支预测需求的架构，其上下文预测可能更具挑战。
