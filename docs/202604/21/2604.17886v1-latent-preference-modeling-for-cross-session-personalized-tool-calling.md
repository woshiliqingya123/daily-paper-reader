## 摘要
用户在向基于大语言模型（LLM）的智能体提出请求时，往往会省略关键细节，导致工具使用的输入信息不足。这对工具增强型智能体提出了根本性挑战，因为 API 执行通常需要完整的参数，从而凸显了对个性化工具调用的需求。为了研究这一问题，我们引入了 MPT，这是一个包含 265 个多会话对话的基准测试，涵盖了三个挑战：偏好召回、偏好归纳和偏好迁移。我们还提出了 PRefine，这是一种测试时内存增强方法，将用户偏好表示为不断演化的假设。通过“生成-验证-细化”循环，它从历史记录中提取可重用的约束条件，并在仅使用全历史提示词所需 token 量的 1.24% 的情况下，提高了工具调用的准确性。这些结果表明，智能体系统中稳健的个性化取决于能够捕捉用户选择背后原因的记忆，而不仅仅是选择本身。

## Abstract
Users often omit essential details in their requests to LLM-based agents, resulting in under-specified inputs for tool use. This poses a fundamental challenge for tool-augmented agents, as API execution typically requires complete arguments, highlighting the need for personalized tool calling. To study this problem, we introduce MPT, a benchmark comprising 265 multi-session dialogues that cover three challenges: Preference Recall, Preference Induction, and Preference Transfer. We also propose PRefine, a test-time memory-augmented method that represents user preferences as evolving hypotheses. Through a generate--verify--refine loop, it extracts reusable constraints from history and improves tool-calling accuracy while using only 1.24% of the tokens required by full-history prompting. These results indicate that robust personalization in agentic systems depends on memory that captures the reasons behind user choices, not just the choices themselves.

*   **核心问题**：在实际应用中，用户向大模型（LLM）智能体发出指令时经常省略关键细节（如“帮我订机票”，但未说明舱位）。现有的工具调用系统往往依赖当前对话或显式用户画像，难以处理**欠指定（Under-specified）**的请求。
*   **研究动机**：作者认为个性化工具调用不仅是一个记忆检索问题，更是一个**推理问题**。智能体需要从跨会话（Cross-session）的历史行为中推断出用户的**潜在偏好**（如“一贯选择经济型方案”），并将其转化为 API 调用中的具体参数约束。

### 2. 方法论：PRefine
*   **核心思想**：将用户偏好视为一种**不断演化的假设（Evolving Hypotheses）**，而非静态事实。通过一个闭环机制在测试时动态维护和更新这些偏好。
*   **关键技术细节（生成-验证-细化循环）**：
    *   **生成（Generate）**：根据当前会话、执行的 API 调用和先前的记忆，生成抽象的偏好假设（如“用户偏好低成本旅游”）。
    *   **验证（Verify）**：由验证器根据四个维度评估假设：证据支持（是否有多次记录）、抽象质量（是否泛化而非复述）、可操作性（是否能约束未来参数）和时间一致性。
    *   **细化（Refine）**：如果假设被拒绝，则根据反馈进行修正，剔除过度特定或无证据的描述。
*   **架构特点**：
    *   **模式无关记忆（Schema-Agnostic Memory）**：存储的是抽象的文本约束，而非特定 API 的键值对，这使得偏好可以在不同工具（Schema）之间迁移。
    *   **轻量化**：仅存储精炼后的偏好描述，极大减少了上下文窗口的占用。

### 6. 主要结论与发现
*   **性能提升**：PRefine 在“偏好归纳”和“偏好迁移”任务上显著优于全量历史提示和 RAG 方法。
*   **极致效率**：PRefine 仅使用了全量历史记录 **1.24%** 的 Token 量，便达到了更高或持平的准确率。
*   **校准能力**：PRefine 生成的 API 参数数量更接近真实值（Ground Truth），减少了冗余参数的幻觉或必要参数的遗漏。
*   **迁移性**：证明了抽象偏好记忆可以无缝应用到全新的 API 领域，解决了工具更新迭代带来的适配问题。

### 7. 优点与亮点
*   **视角独特**：将个性化建模从简单的“信息检索”提升到了“逻辑归纳”的高度。
*   **Token 节省**：对于长程对话系统，98% 以上的 Token 节省具有极高的商业和工程价值。
*   **鲁棒性**：通过生成-验证循环，有效过滤了历史记录中的噪声和一次性偶然行为。

### 8. 不足与局限
*   **分类体系受限**：目前的偏好分组（如预算、旅行人数）相对固定，可能无法覆盖用户所有复杂的潜在动机。
*   **推理延迟**：虽然节省了 Token，但“生成-验证-细化”的循环增加了单次记忆更新时的推理步数和延迟。
*   **保守性风险**：实验观察到某些推理模型在应用 PRefine 后变得过于保守，可能会导致在某些场景下参数生成的召回率略微下降。
