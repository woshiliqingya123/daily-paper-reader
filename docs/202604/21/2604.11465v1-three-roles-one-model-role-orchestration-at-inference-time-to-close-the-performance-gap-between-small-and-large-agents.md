## 摘要
大语言模型 (LLM) 智能体在现实的工具使用任务中展现出潜力，但在适度硬件上部署高性能智能体仍具挑战。我们研究了在不增加任何额外训练计算量的情况下，仅通过推理时脚手架（inference-time scaffolding）能否提升小型模型在复杂多步环境中的性能。在单张 24 GB GPU 上，我们在全精度（FP16，12K 上下文）和 4 位量化（AWQ，32K 上下文）配置下评估了 Qwen3-8B。在没有任何干预的情况下，原始模型仅实现了 5.4% (FP16) 和 3.0% (AWQ) 的任务目标完成率。在系统性故障模式分析的指导下，我们引入了一个三层推理脚手架流水线，将同一个冻结模型部署为三个不同的角色：(1) 摘要模型，在压缩对话历史的同时保留关键工件（token、凭据、API 响应）；(2) 主智能体模型，在压缩后的上下文基础上进行推理；(3) 独立纠错模型，在不访问对话历史的情况下审查并修正智能体的代码输出，从而打破重复的失败循环。应用于同一个未经修改的模型时，该脚手架实现了 8.9% (FP16) 和 5.9% (AWQ) 的任务目标完成率，在两种设置下性能几乎翻倍，尤其在难度 1 的任务上提升显著（FP16 从 15.8% 升至 26.3%；AWQ 从 5.3% 升至 14.0%）。在全精度推理中，我们带有脚手架的 8B 模型超过了原始 AppWorld 评估中的 DeepSeek-Coder 33B Instruct (7.1%)，证明了结构化的推理时干预可以使小型模型具备与 4 倍于其规模的系统竞争的能力。我们将该方法形式化为基于冻结基座模型的脚手架策略，即对同一权重进行三次具有不同条件的调用，并将其与强化学习中的测试时计算缩放和动作空间塑造建立联系。

## Abstract
Large language model (LLM) agents show promise on realistic tool-use tasks, but deploying capable agents on modest hardware remains challenging. We study whether inference-time scaffolding alone, without any additional training compute, can improve the performance of a small model in complex multi-step environments. Operating on a single 24\,GB GPU, we evaluate Qwen3-8B under both full-precision (FP16, 12K context) and 4-bit quantized (AWQ, 32K context) configurations. Without any intervention, the raw model achieves just 5.4\% (FP16) and 3.0\% (AWQ) task goal completion. Guided by a systematic failure mode analysis, we introduce a three-tier inference scaffolding pipeline that deploys the same frozen model in three distinct roles: (1) a summarization model that preserves critical artifacts (tokens, credentials, API responses) while compressing dialogue history; (2) the main agent model that reasons over the compressed context; and (3) an isolated correction model that reviews and revises the agent's code output without access to conversation history, breaking repetitive failure loops. Applied to the same unmodified model, this scaffolding yields 8.9\% (FP16) and 5.9\% (AWQ) task goal completion, roughly doubling performance in both settings, with particularly strong gains on difficulty-1 tasks (15.8\%$\to$26.3\% FP16; 5.3\%$\to$14.0\% AWQ). On full-precision inference, our scaffolded 8B model surpasses DeepSeek-Coder 33B Instruct (7.1\%) from the original AppWorld evaluation, demonstrating that structured inference-time interventions can make small models competitive with systems 4$\times$ their size. We formalize the approach as a scaffolded policy over a frozen base model, three invocations of the same weights with different conditioning, drawing connections to test-time compute scaling and action-space shaping in reinforcement learning.

*   **整体含义**：研究探讨了是否仅通过“推理侧脚手架”（Inference-time Scaffolding）——即改变模型调用结构而非训练模型——就能缩小 8B 模型与 33B 甚至更大模型之间的性能差距。

### 2. 方法论
论文将同一个冻结的 **Qwen3-8B** 模型在推理时分配为三个互补的角色，构建了一个脚手架策略（Scaffolded Policy）：

*   **摘要模型 (Summarizer, $\pi_{sum}$)**：
    *   **核心思想**：解决长对话导致的上下文崩溃。
    *   **技术细节**：当对话历史超过阈值（如 6000 tokens）时触发。它不仅是简单的压缩，而是被指令要求**强制保留关键工件**（如 API 访问令牌、认证凭据、已解决的错误模式和分页状态），确保主智能体不会因上下文截断而“失忆”。
*   **主智能体模型 (Main Agent, $\pi_{agent}$)**：
    *   **核心思想**：执行核心推理。
    *   **技术细节**：基于 ReAct 框架，在压缩后的上下文基础上生成 Python 代码块以调用 API。
*   **纠错模型 (Corrector, $\pi_{correct}$)**：
    *   **核心思想**：打破错误级联。
    *   **关键细节**：该模块被**刻意剥离了对话历史**，仅接收当前生成的代码、API 文档和上一步的执行错误。这种“历史隔离”起到了正则化作用，防止纠错者被主智能体错误的推理逻辑所误导，强制其仅根据 API 文档和执行反馈进行客观修正。

*   **数据集/场景**：**AppWorld**，一个包含 9 个互联应用、457 个 API 端点的真实软件环境基准测试。
*   **Benchmark**：使用 `test_normal` 分区（168 个任务）。
*   **对比方法**：
    *   原始 Qwen3-8B（FP16 全精度与 AWQ 4位量化版）。

*   **评估指标**：任务目标完成率（Task Goal Completion），采用 Pass@1（贪婪解码）。

### 4. 资源与算力
*   **硬件**：单块 **NVIDIA GPU (24 GB VRAM)**。
*   **部署细节**：
    *   **FP16 配置**：使用 vLLM 部署，上下文窗口限制为 12K tokens。
    *   **AWQ 配置**：4位量化，支持完整的 32K tokens 上下文。
*   **训练时长**：**无**。该方法是完全免训练的（Training-free），所有提升均来自推理时的结构化调用。

### 5. 实验数量与充分性
*   **实验规模**：针对 168 个任务进行了多轮测试，包括基准测试、完整脚手架测试以及消融实验。
*   **消融实验**：对比了“仅纠错模块”与“完整脚手架”的效果，验证了各组件的贡献。
*   **分析深度**：利用 GPT-4o 对失败案例进行了系统性的故障模式分析（Failure Mode Analysis），将失败归类为认证问题、推理错误、API 参数错误等。

### 6. 主要结论与发现
*   **性能翻倍**：脚手架使 8B 模型的任务完成率从 5.4% 提升至 **8.9%** (FP16)，在难度 1 的任务上从 15.8% 提升至 26.3%。
*   **以小博大**：全精度的 8B 脚手架模型在数值上超过了参数量大其 4 倍的 **DeepSeek-Coder 33B (7.1%)**。
*   **精度 vs 上下文**：尽管 AWQ 版本有更长的上下文（32K），但 FP16 版本（12K）表现更好，说明对于小型模型，数值精度对推理质量的影响大于上下文长度。
*   **“去掩盖”效应**：脚手架显著减少了机械性错误（如 API 格式错误），从而暴露了模型真正的瓶颈在于核心的“规划与推理”能力。

### 7. 优点
*   **极低成本**：无需微调，仅通过 Prompt 工程和推理逻辑编排即可实现显著增益。
*   **诊断驱动设计**：脚手架的设计直接针对故障模式分析中发现的“认证丢失”和“重复循环”问题，具有很强的针对性。
*   **角色隔离机制**：纠错模块不看历史记录的设计非常巧妙，有效打破了智能体常见的自我强化错误循环。

### 8. 不足与局限
*   **统计显著性不足**：由于 AppWorld 测试集规模限制，8B 模型超越 33B 模型的结论在 95% 置信水平下尚不具备显著性差异。
*   **高难度任务瓶颈**：对于难度 3 的任务，脚手架几乎没有提升，说明推理侧干预无法弥补模型底层逻辑推理能力的缺失。
*   **纠错模块的副作用**：在极长程任务中，纠错模块因缺乏历史信息，有时会幻化出错误的占位符（如用户 ID），导致修正失败。
*   **单一模型验证**：实验主要集中在 Qwen 系列，尚未在其他 7B/8B 规模的模型（如 Llama-3 或 Mistral）上广泛验证通用性。
