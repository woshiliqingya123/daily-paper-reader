## 摘要
近期大语言模型（LLMs）的进展已成功采用基于搜索的策略来增强代码生成。然而，现有方法通常依赖静态且稀疏的公开测试用例进行验证，导致了“伪正确性”问题——即解决方案过拟合于可见的公开测试，但无法泛化到隐藏的测试用例。我们认为，针对固定且薄弱的环境进行优化本质上限制了鲁棒性。为解决这一问题，我们提出了 AdverMCTS，这是一种新型的对抗性蒙特卡洛树搜索框架，通过将代码搜索与主动漏洞发现相结合来应对伪正确性。AdverMCTS 将生成过程建模为求解器（Solver）智能体与攻击者（Attacker）智能体之间的极大极小博弈；其中求解器负责合成候选代码，而攻击者则通过演化生成针对性的边界测试用例，以利用当前代码池中的逻辑差异。这些发现的测试构成了一个动态的、敌对性逐渐增强的过滤器，从而惩罚脆弱的推理。大量实验表明，AdverMCTS 显著优于现有最先进的基准方法，有效地降低了误报率，并迫使模型在初始约束之外进行泛化。本工作的资源可在 https://anonymous.4open.science/r/AdverMCTS_open-A255 获取。

## Abstract
Recent advancements in Large Language Models (LLMs) have successfully employed search-based strategies to enhance code generation. However, existing methods typically rely on static, sparse public test cases for verification, leading to pseudo-correctness -- where solutions overfit the visible public tests but fail to generalize to hidden test cases. We argue that optimizing against a fixed, weak environment inherently limits robustness. To address this, we propose AdverMCTS, a novel adversarial Monte Carlo Tree Search framework that combats pseudo-correctness by coupling code search with active vulnerability discovery. AdverMCTS formulates generation as a minimax-style game between a Solver agent, which synthesizes code candidates, and an Attacker agent, which evolves to generate targeted corner test cases that exploit logical divergences in the current code pool. These discovered tests form a dynamic, progressively hostile filter that penalizes fragile reasoning. Extensive experiments demonstrate that AdverMCTS significantly outperforms state-of-the-art baselines, effectively reducing false positive rates and forcing the model to generalize beyond the initial constraints. #### 1. 核心问题与整体含义（研究动机和背景）
论文关注的核心问题是代码生成中的**“伪正确性”（Pseudo-Correctness）**。
*   **背景**：现有的基于搜索的代码生成方法（如 LATS、ToT）主要依赖稀疏的公开测试用例（Public Tests）进行验证。
*   **动机**：公开测试通常只是简单的“冒烟测试”，导致生成的代码容易出现过拟合现象——即代码能通过公开测试，但在逻辑上无法泛化到隐藏的边界情况（Hidden Tests）。
*   **核心含义**：作者认为瓶颈不在于求解器（Solver）生成正确代码的能力，而在于验证环境区分正确与错误代码的能力。因此，需要一种动态的、具有对抗性的验证机制来“逼出”代码中的潜在漏洞。

#### 2. 方法论：核心思想与关键技术
AdverMCTS 提出了一个**双智能体对抗博弈框架**，将代码生成建模为求解器与攻击者之间的极大极小（Minimax）博弈。

*   **求解器 MCTS (Solver Agent)**：
    *   **搜索空间**：在思维链（CoT）步骤上进行搜索。
    *   **代码合成**：在模拟（Simulation）阶段生成完整的候选代码。
    *   **混合反馈**：奖励信号由公开测试通过率（正向）和来自攻击者的惩罚信号（负向）组成。
*   **攻击者 MCTS (Attacker Agent)**：
    *   **核心任务**：针对当前代码池（Code Pool）寻找能诱发行为差异的测试输入。
    *   **分歧驱动测试合成 (DMTS)**：攻击者观察代码池中不同候选代码的输出，如果某个输入导致不同代码产生不同输出（Divergence），则认为该输入具有高奖励（$R_{div}$），因为它成功暴露了逻辑歧义。
*   **全局过滤中心 (Global Filtering Hub)**：
    *   **LLM 仲裁器 (Arbiter)**：当代码输出不一致时，调用 LLM 作为裁判，根据题目描述判定哪个输出是正确的，从而生成带标签的对抗性测试用例。
    *   **动态约束**：发现的对抗性用例被加入全局过滤器，后续生成的代码必须通过这些“硬约束”才能进入代码池。
*   **推理阶段**：采用分层重排序策略，先按公开测试通过率排序，再按对抗性测试通过率排序，选出最终代码。

*   **性能领先**：AdverMCTS 在所有难度等级上均显著优于现有搜索方法，尤其在竞赛级题目上提升明显。

*   **协同演化**：实验观察到，随着对抗性测试用例的积累，代码池的隐藏测试通过率同步上升，验证了对抗压力的正面引导作用。
*   **误报减少**：攻击者能识别出超过 50% 的“静默错误”（即通过公开测试但逻辑错误的代码）。

#### 7. 优点
*   **范式创新**：将静态验证转变为动态对抗，解决了代码生成中长期存在的“伪正确”瓶颈。
*   **无需外部 Oracle**：利用代码池的分歧和 LLM 仲裁，在测试时自主生成高质量的验证信号。
*   **模型无关性**：实验证明该方法在小模型和大模型上均能带来一致的性能增益。

#### 8. 不足与局限
*   **仲裁器依赖**：虽然 LLM 仲裁器的准确率较高（约 80%），但仍存在 20% 的误判风险，可能导致错误的惩罚信号。

*   **语言限制**：实验主要集中在 Python 语言，对于其他缺乏成熟执行环境或仲裁能力的编程语言，其效果尚待验证。
