## 摘要
我们研究了功能性多数投票（Functional Majority Voting, FMV），这是一种基于功能一致性的大语言模型代码生成方法，该方法利用在测试输入上的运行时执行特征，从多个生成的候选项中识别出具有代表性的解决方案。我们发现 FMV 是一种有效的测试时推理策略，在不产生巨大计算开销的情况下，显著提升了在 LiveCodeBench 上的性能。此外，我们扩展了功能一致性的应用范围，将其作为无标签测试时强化学习（Test-Time Reinforcement Learning）的聚合策略。我们证明了该方法提高了留出任务上的 pass@1 指标，但并未发现其能实现超越基础模型性能上限的自我提升。

## Abstract
We investigate Functional Majority Voting (FMV), a method based on functional consensus for code generation with Large Language Models, which identifies a representative solution from multiple generations using their runtime execution signatures on test inputs. We find that FMV is an effective test-time inference strategy, substantially boosting performance on LiveCodeBench without a large compute overhead. Furthermore, we extend the utility of functional consensus and apply it as an aggregation strategy for label-free Test-Time Reinforcement Learning. We demonstrate that this increases pass@1 on holdout tasks, but find no evidence of self-improvement beyond the base model's performance ceiling.

### 2. 论文提出的方法论
论文提出了 **功能性多数投票（Functional Majority Voting, FMV）**，包含两种应用方式：
*   **FMV 推理策略（Functional Medoid）**：
    *   **核心思想**：对同一个问题生成 $N$ 个候选程序，在 $K$ 个测试输入上运行。
    *   **算法流程**：收集每个程序的执行结果向量。计算每个程序与其他程序在输出结果上的匹配程度（得分 $S(c_i)$）。得分最高的程序被视为“功能中心点”（Medoid），即共识解。
    *   **软匹配**：不同于传统的严格一致性（要求所有测试用例全对），FMV 允许在部分测试用例上匹配，从而对具有鲁棒性的程序给予“部分信用”。
*   **Pointwise-FMV（合成目标）**：
    *   用于测试时强化学习（TTRL）。它不选择单个程序，而是针对每个测试用例，取所有候选程序输出结果的“众数”，构建一个合成的执行向量作为伪标签。

### 6. 主要结论与发现

*   **TTRL 的局限性**：虽然通过 FMV 引导的强化学习提升了模型的零样本（Zero-shot）表现，但它**未能提高模型的性能天花板（best@64）**。
*   **摊销效应**：模型在 TTRL 训练后，实际上是“摊销”了推理时的搜索增益，将多次采样的优势转化为了单次生成的准确率，但并没有产生真正的“自我进化”。

### 7. 优点
*   **高效性**：FMV 纯靠执行结果匹配，无需额外的模型调用，适合大规模部署。
*   **鲁棒性**：通过软匹配机制，FMV 能够处理那些在边缘情况有微小差异但逻辑正确的程序。
*   **即插即用**：作为一种推理策略，它可以直接应用于任何现有的代码生成模型。

### 8. 不足与局限
*   **性能天花板限制**：实验证明该方法无法让模型学到其采样空间之外的知识，即无法突破“基础模型上限”。
*   **错误共识风险**：论文提到，模型有时会对错误的解达成一致（Lucky Hit 现象的失效），导致强化学习强化了错误的逻辑。
