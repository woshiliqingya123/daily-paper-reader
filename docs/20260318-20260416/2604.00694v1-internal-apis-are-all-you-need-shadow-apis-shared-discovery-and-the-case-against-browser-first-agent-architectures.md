## 摘要
自主智能体越来越多地与 Web 交互，但大多数网站仍是为人类浏览器设计的——这是新兴的“智能体化网络”（Agentic Web）必须解决的根本性不匹配。智能体必须重复浏览页面、检查 DOM 并逆向工程可调用路由，这一过程缓慢、脆弱，且在不同智能体之间冗余重复。我们观察到，每个现代网站在其用户界面背后都已经暴露了内部 API（有时称为影子 API），即驱动网站自身功能的甲方端点。我们提出了 Unbrowse，这是一个共享路由图，它将基于浏览器的路由发现转化为这些可调用甲方接口的集体维护索引。该系统从真实的浏览流量中被动学习路由，并通过直接 API 调用提供缓存路由。在一项涵盖 94 个域名的等效信息检索任务的单主机实时网络基准测试中，完全预热的缓存执行平均耗时 950 毫秒，而 Playwright 浏览器自动化耗时 3,404 毫秒（平均加速 3.6 倍，中位数加速 5.4 倍），缓存良好的路由可在 100 毫秒内完成。三路径执行模型（本地缓存、共享图或浏览器回退）确保了系统的自愿性和自我修正。通过 x402 协议建立的三层微支付模型对图查询收取单次查询搜索费（第 3 层），对发现文档收取一次性安装费（第 1 层），并为选择加入的网站所有者提供可选的单次执行费（第 2 层）。所有层级都基于理性采用的必要条件：只有当总费用低于浏览器重新发现的预期成本时，智能体才会使用共享图。

## Abstract
Autonomous agents increasingly interact with the web, yet most websites remain designed for human browsers -- a fundamental mismatch that the emerging ``Agentic Web'' must resolve. Agents must repeatedly browse pages, inspect DOMs, and reverse-engineer callable routes -- a process that is slow, brittle, and redundantly repeated across agents. We observe that every modern website already exposes internal APIs (sometimes called \emph{shadow APIs}) behind its user interface -- first-party endpoints that power the site's own functionality. We present Unbrowse, a shared route graph that transforms browser-based route discovery into a collectively maintained index of these callable first-party interfaces. The system passively learns routes from real browsing traffic and serves cached routes via direct API calls. In a single-host live-web benchmark of equivalent information-retrieval tasks across 94 domains, fully warmed cached execution averaged 950\,ms versus 3{,}404\,ms for Playwright browser automation (3.6$\times$ mean speedup, 5.4$\times$ median), with well-cached routes completing in under 100\,ms. A three-path execution model -- local cache, shared graph, or browser fallback -- ensures the system is voluntary and self-correcting. A three-tier micropayment model via the x402 protocol charges per-query search fees for graph lookups (Tier~3), a one-time install fee for discovery documentation (Tier~1), and optional per-execution fees for site owners who opt in (Tier~2). All tiers are grounded in a necessary condition for rational adoption: an agent uses the shared graph only when the total fee is lower than the expected cost of browser rediscovery.

### 1. 核心问题与整体含义
*   **研究动机**：目前的网页智能体主要通过模拟人类行为（如解析 DOM、点击 UI）与网页交互。这种“浏览器优先”的架构存在三大痛点：**慢**（加载完整页面耗时）、**脆**（UI 微调即导致脚本失效）、**冗余**（不同智能体在同一网站上重复进行逆向工程）。
*   **核心观察**：现代网站在 UI 背后都运行着内部 API（影子 API），这些接口直接驱动功能且更易于机器处理。
*   **整体含义**：论文主张“内部 API 就是你所需的一切”，提议构建一个共享的路由图（Shared Route Graph），将智能体的重复劳动转化为集体维护的 API 索引，从而实现“智能体化网络”（Agentic Web）的高效协作。

### 2. 方法论
*   **核心思想**：通过被动学习真实浏览流量，自动提取并索引网站的内部 API 路由，供所有智能体共享调用。
*   **三路径执行模型**：
    1.  **路径 1（本地缓存）**：优先检查本地是否已有该任务的路由缓存。
    2.  **路径 2（共享图）**：若本地无缓存，则查询云端共享索引，通过 x402 协议支付微量费用获取 API 路由文档。
    3.  **路径 3（浏览器回退）**：若索引中无匹配路由，则启动轻量级浏览器（Kuri）进行实时捕获和逆向工程，并将新发现的路由发布到共享图。
*   **关键技术细节**：
    *   **Kuri 代理**：使用 Zig 语言编写的轻量级 CDP 经纪人，替代沉重的 Playwright 框架。
    *   **x402 协议**：基于区块链的微支付协议，实现路由发现者、维护者和基础设施之间的自动化收益分成。
    *   **增量贡献归属**：采用基于 Delta 的机制，根据贡献者对路由模式、参数架构改进的边际贡献分配奖励。
*   **经济公式**：智能体采用共享图的必要条件是：$f_{route} < c_{rediscovery}$（即购买路由的费用必须低于自行通过浏览器重新发现的预期成本，包括延迟、算力和 Token 消耗）。

### 3. 实验设计
*   **实验场景**：在 94 个真实域名（涵盖政府、SaaS、电商、医疗、金融等）上执行等效的信息检索任务。
*   **Benchmark**：对比 **Unbrowse（缓存 API 调用）** 与 **Playwright（浏览器自动化）**。
*   **任务设计**：要求两者返回语义等效的结构化数据（如“某产品的当前价格”），确保对比的公平性。
*   **测试环境**：单主机实时网络环境（新加坡住宅宽带）。

### 4. 资源与算力
*   **硬件设备**：实验在一台配备 **M4 Max 芯片、64GB 统一内存的 MacBook Pro** 上完成。
*   **算力说明**：论文未涉及大规模 GPU 集群训练，其核心贡献在于系统架构和实时推理效率。浏览器运行成本约为每个实例 500MB RAM。

### 5. 实验数量与充分性
*   **实验规模**：
    *   **热启动测试**：针对 94 个域名进行了 3 轮测试，取第 3 轮（预热后）数据。
    *   **冷启动测试**：针对 20 个新域名测试了从“浏览器发现”到“发布路由”的全过程。
*   **充分性评价**：实验覆盖了多样化的域名类别，并提供了详细的延迟分布和加速比分析。虽然是单主机测试，但通过对比同一网络环境下的两种路径，客观地展示了 API 调用的性能优势。不过，缺乏大规模多智能体经济系统的长期演化模拟。

### 6. 主要结论与发现
*   **显著加速**：在 94 个域名中，Unbrowse 的平均延迟为 **950 毫秒**，而 Playwright 为 **3,404 毫秒**。
*   **性能倍率**：平均加速 **3.6 倍**，中位数加速 **5.4 倍**，部分站点最高可达 **30 倍**。
*   **成本摊销**：冷启动虽然耗时较长（中位数 8.2 秒），但只需执行一次。通常在 **3-5 次** 复用后，API 模式的成本优势即可抵消初始发现成本。
*   **网络效应**：随着更多智能体加入，共享图的覆盖范围和准确性会自我增强。

### 7. 优点
*   **架构创新**：跳出了“模拟人类点击”的思维定式，利用影子 API 实现了数量级的效率提升。
*   **经济激励**：引入 x402 微支付和 Delta 归属机制，解决了开源知识库常见的“公地悲剧”和维护动力不足问题。
*   **实用性强**：系统设计了完善的回退机制，确保在 API 失效或不存在时仍能通过浏览器完成任务。

### 8. 不足与局限
*   **反爬虫挑战**：对于部署了高级 Web 应用防火墙（如 Cloudflare 高级版）的站点，非浏览器流量仍可能被拦截。
*   **安全风险**：恶意贡献者可能发布钓鱼路由，虽然有本地执行和验证机制，但仍存在对抗性风险。
*   **法律灰色地带**：对于未明确授权 API 访问的站点，这种“影子 API”调用在法律和道德层面仍存在争议（尽管论文提倡站点所有者通过 Tier 2 模式参与分成）。
*   **地理偏差**：实验数据基于新加坡节点，全球不同地区的延迟表现可能存在差异。
