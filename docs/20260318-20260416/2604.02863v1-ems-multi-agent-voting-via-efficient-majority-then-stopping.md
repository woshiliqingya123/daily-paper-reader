## 摘要
多数投票是将多智能体响应聚合为最终决策的标准方法。然而，传统方法通常要求所有智能体在聚合开始前完成推理，这导致了显著的计算开销，因为一旦达成多数共识，许多响应就变得冗余。在这项工作中，我们将多智能体投票建模为一个可靠性感知的智能体调度问题，并提出了一种高效的“多数即停止”（Efficient Majority-then-Stopping, EMS）机制来提高推理效率。EMS 根据任务感知的可靠性对智能体进行优先级排序，并在达成多数意见的瞬间终止推理流水线。该方法由以下三个关键组件构成：具体而言，我们引入了智能体置信度建模（ACM），利用历史表现和语义相似度来估计智能体的可靠性；自适应增量投票（AIV），用于顺序选择智能体并实现提前停止；以及个体置信度更新（ICU），用于动态更新每个参与智能体的可靠性。在六个基准测试上的广泛评估表明，EMS 能够稳定地将调用的智能体平均数量减少 32%。

## Abstract
Majority voting is the standard for aggregating multi-agent responses into a final decision. However, traditional methods typically require all agents to complete their reasoning before aggregation begins, leading to significant computational overhead, as many responses become redundant once a majority consensus is achieved. In this work, we formulate the multi-agent voting as a reliability-aware agent scheduling problem, and propose an Efficient Majority-then-Stopping (EMS) to improve reasoning efficiency. EMS prioritizes agents based on task-aware reliability and terminates the reasoning pipeline the moment a majority is achieved from the following three critical components. Specifically, we introduce Agent Confidence Modeling (ACM) to estimate agent reliability using historical performance and semantic similarity, Adaptive Incremental Voting (AIV) to sequentially select agents with early stopping, and Individual Confidence Updating (ICU) to dynamically update the reliability of each contributing agent. Extensive evaluations across six benchmarks demonstrate that EMS consistently reduces the average number of invoked agents by 32%.

*   **核心问题**：在多智能体系统（MAS）中，**多数投票（Majority Voting）**是聚合决策的标准方法，但传统做法要求所有智能体（如 $N$ 个）全部完成推理后才进行统计。
*   **研究动机**：作者发现这种“先推理、后聚合”的模式存在巨大的计算浪费。实际上，一旦有超过半数（$\lceil (N+1)/2 \rceil$）的智能体达成共识，后续智能体的推理结果已无法改变最终决策。
*   **目标**：将投票过程建模为“可靠性感知”的调度问题，通过优化智能体调用顺序并引入早停机制，在不损失准确率的前提下显著提升推理效率。

### 2. 方法论：EMS 框架
EMS（Efficient Majority-then-Stopping）框架包含三个核心组件：

*   **智能体置信度建模 (ACM)**：
    *   **历史可靠性**：计算智能体在过去任务中与最终共识一致的比例。
    *   **语义相似度**：维护一个语义历史缓冲区，存储智能体回答正确的问题嵌入（Embedding）。对于新问题，计算其与缓冲区内容的相似度，以评估该智能体处理此类问题的“专长”。
*   **自适应增量投票 (AIV)**：
    *   **初始投票**：首先调用排序最靠前的 $\tau = \lceil (N+1)/2 \rceil$ 个智能体。
    *   **增量检查**：如果初始 $\tau$ 个智能体未达成共识，则按可靠性降序逐个引入后续智能体。
    *   **早停机制**：在每一步增量后立即检查是否已有答案获得 $\tau$ 票，一旦满足则立即终止流水线并输出结果。
*   **个体置信度更新 (ICU)**：
    *   动态更新参与投票智能体的状态（参与次数、正确次数、语义缓冲区），确保调度策略随任务进行而进化。

### 6. 主要结论与发现

### 7. 优点
*   **即插即用**：不需要对底层 LLM 进行微调，适用于任何现有的多智能体投票系统。
*   **成本优化明显**：直接减少了 API 调用次数或推理算力消耗，具有极高的工程实践价值。
*   **动态进化**：通过 ICU 组件，系统能够根据智能体的实时表现自动调整调度策略。

### 8. 不足与局限
*   **串行延迟风险**：虽然减少了总计算量，但“逐个增加智能体”的增量模式在最坏情况下（难以达成共识的任务）会增加**推理延迟（Latency）**，因为无法像传统 MV 那样完全并行。
*   **排序依赖性**：如果初始排序策略失效（例如所有智能体对某类新题型都表现不佳），效率提升将不明显。
*   **实验覆盖**：主要集中在客观选择题或有标准答案的推理题，对于开放式生成任务（如创意写作）的适用性尚未验证。
