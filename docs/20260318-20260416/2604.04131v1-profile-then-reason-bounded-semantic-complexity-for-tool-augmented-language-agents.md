## 摘要
使用外部工具的大语言模型智能体通常通过反应式执行来实现，即在每次观察后重复重新计算推理，这增加了延迟和对错误传播的敏感性。本研究引入了“先画像后推理”（Profile-Then-Reason, PTR），这是一种用于结构化工具增强推理的有界执行框架。在该框架中，语言模型首先合成一个显式工作流，由确定性或受保护的算子执行该工作流，验证器评估生成的轨迹，并且仅在原始工作流不再可靠时才调用修复机制。本文开发了一种数学公式，将整个流水线表示为画像、路由、执行、验证、修复和推理算子的组合；在有界修复下，语言模型调用次数在名义情况下被限制为两次，在最坏情况下为三次。在六个基准测试和四个语言模型上与 ReAct 基准进行的对比实验表明，PTR 在 24 种配置中的 16 种里实现了成对精确匹配优势。结果表明，PTR 在以检索为中心和重分解的任务中特别有效，而当成功取决于大量的在线适应时，反应式执行仍然更具优势。

## Abstract
Large language model agents that use external tools are often implemented through reactive execution, in which reasoning is repeatedly recomputed after each observation, increasing latency and sensitivity to error propagation. This work introduces Profile--Then--Reason (PTR), a bounded execution framework for structured tool-augmented reasoning, in which a language model first synthesizes an explicit workflow, deterministic or guarded operators execute that workflow, a verifier evaluates the resulting trace, and repair is invoked only when the original workflow is no longer reliable. A mathematical formulation is developed in which the full pipeline is expressed as a composition of profile, routing, execution, verification, repair, and reasoning operators; under bounded repair, the number of language-model calls is restricted to two in the nominal case and three in the worst case. Experiments against a ReAct baseline on six benchmarks and four language models show that PTR achieves the pairwise exact-match advantage in 16 of 24 configurations. The results indicate that PTR is particularly effective on retrieval-centered and decomposition-heavy tasks, whereas reactive execution remains preferable when success depends on substantial online adaptation.

### 1. 核心问题与整体含义
该论文针对当前工具增强型大语言模型（LLM）智能体主流的“反应式执行”（Reactive Execution，如 ReAct）模式存在的缺陷进行了研究。反应式执行在每一步观察后都要重新调用 LLM 进行推理，导致了**高延迟、高成本**以及**错误容易在推理链中传播**的问题。论文的核心动机是：在许多结构化任务中，工作流是相对可预测的，不需要在每一步都进行昂贵的语义重计算。因此，作者提出了 **Profile-Then-Reason (PTR)** 框架，旨在通过“有界语义复杂度”（即限制 LLM 调用次数）来提高智能体的效率和稳健性。

### 2. 方法论
PTR 框架将智能体的执行过程从“推理-行动-观察”的循环转变为一个结构化的流水线，核心思想是**将语义规划与确定性执行分离**。

*   **核心流程（六个阶段）：**
    1.  **PROFILE（画像/规划）：** LLM 仅调用一次，合成一个显式的工作流（Workflow），包含工具调用序列、参数占位符、分支规则和不确定性描述。
    2.  **ROUTE（路由）：** 基于风险函数 $R(m, p)$ 确定执行模式（纯执行、受保护执行或可修复执行）。这是一个确定性的数学计算过程。
    3.  **EXECUTE（执行）：** 在确定性算子下运行工作流。利用“自动解析规则”处理中间参数，利用“分支规则”处理局部逻辑，无需 LLM 介入。
    4.  **VERIFY（验证）：** 确定性地评估执行轨迹的信任分数 $\kappa$。如果分数过低或发生硬故障，则触发修复。
    5.  **REPAIR（修复，可选）：** 仅在必要时调用第二次（或第三次）LLM，针对故障点修补工作流。
    6.  **REASON（推理/总结）：** 最后一次 LLM 调用，基于执行轨迹生成最终报告。
*   **关键技术细节：** 引入了有界修复（Bounded Repair）概念，确保在名义情况下仅需 2 次 LLM 调用，最坏情况下不超过 3 次，从而将语义复杂度控制在常数范围内。

    *   **事实检索：** TriviaQA, NQ-Open。

### 6 主要结论与发现
*   **性能优势：** PTR 在 24 种配置中的 16 种（67%）表现优于 ReAct。
*   **任务适配性：** PTR 在**检索中心型**（如 TriviaQA）和**重分解型**（如 StrategyQA）任务中优势巨大；但在需要**高度在线适应**（如 HotPotQA 的多跳检索）或**自由符号操作**（如 AQuA-RAT）的任务中，ReAct 仍然占优。
*   **成本效益：** PTR 总体成本比 ReAct 降低了约 **12%**，且在大多数情况下实现了更高的精确匹配（EM）得分。
*   **模型交互：** 弱模型（如 GPT-4o-Mini）在 PTR 的结构化脚手架下受益最明显。

### 7. 优点
*   **高效性：** 显著减少了 LLM 调用次数，降低了推理延迟和 API 成本。
*   **可观察性：** 将执行过程转化为结构化的状态转换，比 ReAct 的对话式轨迹更易于审计和调试。
*   **稳健性：** 通过确定性规则处理局部错误，避免了 LLM 在中间步骤产生幻觉导致的错误累积。

### 8. 不足与局限
*   **灵活性受限：** 预规划模式难以应对那些“下一步行动完全取决于前一步未知观察结果”的极动态任务。
*   **启发式依赖：** 路由和验证阶段依赖于人工设计的风险/信任函数，这些函数的通用性和参数敏感性仍需进一步研究。
*   **应用范围：** 目前主要适用于工具调用逻辑相对固定的结构化领域，不一定是所有开放式探索任务的通用替代方案。
