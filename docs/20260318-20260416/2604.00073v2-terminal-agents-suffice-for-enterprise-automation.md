## 摘要
人们对于构建能够与数字平台交互以自主执行有意义的企业任务的智能体表现出日益增长的兴趣。在已探索的方法中，包括基于模型上下文协议（MCP）等抽象构建的工具增强型智能体，以及通过图形界面操作的网页智能体。然而，考虑到成本和运行开销，目前尚不清楚此类复杂的智能体系统是否必要。我们认为，仅配备终端和文件系统的编程智能体，通过直接与平台 API 交互，可以更有效地解决许多企业任务。我们在多种真实世界系统中评估了这一假设，并表明这些底层终端智能体的表现与更复杂的智能体架构相当甚至更优。我们的研究结果表明，简单的编程接口结合强大的基础模型，足以满足实际的企业自动化需求。

## Abstract
There has been growing interest in building agents that can interact with digital platforms to execute meaningful enterprise tasks autonomously. Among the approaches explored are tool-augmented agents built on abstractions such as Model Context Protocol (MCP) and web agents that operate through graphical interfaces. Yet, it remains unclear whether such complex agentic systems are necessary given their cost and operational overhead. We argue that a coding agent equipped only with a terminal and a filesystem can solve many enterprise tasks more effectively by interacting directly with platform APIs. We evaluate this hypothesis across diverse real-world systems and show that these low-level terminal agents match or outperform more complex agent architectures. Our findings suggest that simple programmatic interfaces, combined with strong foundation models, are sufficient for practical enterprise automation.

### 6. 主要结论与发现
*   **性能领先**：终端智能体在成功率上匹配或超越了 Web 智能体，且远超 MCP 智能体。
*   **成本极低**：终端智能体的推理成本通常比 Web 智能体低 **5 到 10 倍**（例如在 ServiceNow 上，Web 智能体成本是终端智能体的 4-6 倍）。
*   **MCP 的局限**：MCP 智能体受限于工具覆盖范围，即使在“可行任务子集”中，也因接口僵化而表现不佳。
*   **技能积累的价值**：允许智能体记录“技能”能显著提升成功率并进一步降低成本（ServiceNow 上成本降低 43.7%）。
*   **文档的副作用**：如果文档是面向 UI 的而非面向 API 的，反而会误导智能体采取复杂的错误策略。

### 7. 优点与亮点
*   **大道至简**：挑战了“越复杂越好”的固有思维，证明了底层接口（API+终端）在企业级任务中的强大生命力。
*   **实用性强**：实验基于真实生产级平台，结论对企业落地 AI 智能体具有直接的指导意义（即：优先开放 API 而非开发复杂工具包）。
*   **贡献显著**：引入了 ERPNext 这一新的企业自动化基准测试，丰富了该领域的评估手段。

### 8. 不足与局限
*   **UI 依赖型任务**：对于必须通过图形界面完成的操作（如拖拽式流程设计器、读取复杂的动态图表），终端智能体无能为力。
*   **API 门槛**：该方法高度依赖于平台提供稳定且表达能力强的 API。
*   **安全风险**：赋予智能体终端访问权限具有较高的安全风险，需要严格的沙盒隔离和权限控制（RBAC）。
*   **模型依赖**：终端智能体要求模型具备极强的代码编写和 API 探索能力，较弱的模型可能无法胜任。
