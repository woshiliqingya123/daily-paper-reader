## Abstract
Frontier LLMs can navigate complex websites, but their cost and reliance on third-party APIs make local deployment impractical. We introduce Agent-as-Annotators, a framework that structures synthetic trajectory generation for web agents by analogy to human annotation roles, replacing the Task Designer, Annotator, and Supervisor with modular LLM components. Using Gemini 3 Pro as teacher, we generate 3,000 trajectories across six web environments and fine-tune a 9B-parameter student with pure supervised learning on the 2,322 that pass quality filtering. The resulting model achieves 41.5% on WebArena, surpassing closed-source models such as Claude 3.5 Sonnet (36.0%) and GPT-4o (31.5%) under the same evaluation protocol, and nearly doubling the previous best open-weight result (Go-Browse, 21.7%). Capabilities transfer to unseen environments, with an 18.2 percentage point gain on WorkArena L1 (an enterprise platform never seen during training) and consistent improvements across three additional benchmarks. Ablations confirm that each pipeline component contributes meaningfully, with Judge filtering, evaluation hints, and reasoning traces each accounting for measurable gains. These results demonstrate that structured trajectory synthesis from a single frontier teacher is sufficient to produce competitive, locally deployable web agents. ### 1. 核心问题与整体含义（研究动机和背景）
*   **核心问题**：前沿大语言模型（如 GPT-4o, Claude 3.5）虽然具备强大的网页导航能力，但由于其高昂的 API 成本、隐私风险以及对第三方服务的依赖，难以在本地部署。而现有的中小型开源模型（约 9B 参数）在网页任务上的表现远逊于闭源模型（差距超过 22 个百分点）。
*   **研究动机**：探索如何通过“智能体能力蒸馏”（Agentic Capability Distillation），利用强大的教师模型生成高质量的合成训练数据，从而提升小型开源模型在复杂网页任务中的性能和泛化能力。

### 2. 方法论：AGENT-AS-ANNOTATORS 框架
该框架通过类比人类标注网页基准测试的过程，将合成轨迹生成分为两个阶段和三个角色：
*   **第一阶段：任务合成（模拟任务设计者）**
    *   **Persona Generator（人格生成器）**：生成多样化的用户背景和目标，以诱导不同的任务分布。
    *   **Task Generator（任务生成器）**：在环境中探索并合成任务意图（Intent），同时生成基于环境状态的**评估提示（Evaluation Hints）**。
*   **第二阶段：轨迹收集与过滤（模拟标注者与监督者）**
    *   **Agent（标注者）**：仅根据任务意图在环境中执行操作，生成交互轨迹。
    *   **Judge（监督者）**：利用教师模型作为裁判，结合“评估提示”对轨迹进行严格筛选。
*   **关键技术细节**：
    *   **特权信息利用**：教师模型在生成任务时拥有环境探索的“特权信息”（即 Hints），但在学生模型训练时，这些 Hints 不会被提供，确保学生模型学习的是纯粹的任务解决能力。
    *   **推理链（Reasoning Traces）**：保留教师模型在每一步操作前的思考过程（`<thought>` 标签），并将其作为监督微调（SFT）的目标之一。

### 3. 实验设计
*   **数据集/场景**：
    *   **训练集（A3-SYNTH）**：在 WebArena 的 6 个自托管环境（Reddit、GitLab、购物、购物后台、维基百科、地图）中生成了 3,000 个任务，最终筛选出 2,322 条成功轨迹（约 1.6 万个训练样本）。
*   **基准测试（Benchmarks）**：
    *   **WebArena**（域内测试）：评估在已知环境下的新任务表现。
    *   **VisualWebArena**、**WorkArena L1/L2**（企业级平台）、**MiniWoB**：评估跨环境、跨视觉任务和原子技能的泛化能力。
*   **对比方法**：
    *   **闭源模型**：Gemini 3 Pro/Flash, GPT-4o, Claude 3.5 Sonnet。
    *   **开源基座模型**：Qwen3.5 系列（2B, 4B, 9B, 27B）。
    *   **先前蒸馏方法**：Go-Browse, NNetNav 等。

### 4. 资源与算力
*   **训练算力**：使用了 4 到 8 张 GPU（型号包括 **NVIDIA A100 80GB** 或 **H200 141GB**）。
*   **训练时长**：对于 9B 参数的模型，在 8 张 GPU 上进行 2 个 epoch 的微调大约需要 **12-16 小时**。
*   **推理/评估**：使用 vLLM 框架在 2 张 GPU 上进行推理。

### 5. 实验数量与充分性
*   **实验规模**：生成了 3,000 条轨迹，涵盖 250 个不同的人格。
*   **消融实验**：非常充分。研究者针对**数据规模**（从 285 到 2322 条轨迹）、**裁判过滤（Judge）**、**推理链（Reasoning）**、**评估提示（Hints）**以及**教师模型质量**（不同版本的 Gemini）分别进行了对比实验。
*   **客观性**：使用了统一的 BrowserGym 评估协议，确保了与闭源模型对比的公平性。

### 6. 主要结论与发现
*   **性能突破**：微调后的 **A3-Qwen3.5-9B** 在 WebArena 上达到 **41.5%** 的成功率，不仅远超此前的开源模型（21.7%），甚至超越了 GPT-4o (31.5%) 和 Claude 3.5 Sonnet (36.0%)。
*   **泛化能力强**：在完全未见过的企业级平台 WorkArena L1 上，性能提升了 **18.2 个百分点**。
*   **质量胜过数量**：实验发现，教师模型的质量比数据量更重要。
*   **反直觉发现**：降低教师模型的“思考预算”（Thinking Budget）反而生成了更高质量、更简洁的训练轨迹，更有利于学生模型学习。

### 7. 优点
*   **结构化框架**：将复杂的智能体数据生成过程模块化，为后续研究提供了清晰的可对比路径。
*   **评估提示（Hints）的引入**：有效解决了网页任务中“最终状态难以判定”的问题，显著提升了合成数据的标签准确性。
*   **高效蒸馏**：证明了仅需数千条高质量轨迹，即可让 9B 模型具备挑战顶级闭源模型的能力。

### 8. 不足与局限
*   **环境多样性有限**：虽然泛化性表现良好，但训练环境仅限于 WebArena 的 6 个站点，尚未在更大规模的真实互联网环境下验证。
*   **裁判偏差风险**：Judge 模块依然依赖 LLM，可能存在假阳性（False Positive）判断，且未与人类标注进行大规模的一致性校验。
*   **仅限于 SFT**：论文主要关注监督微调，尚未结合强化学习（RL）进行进一步的性能优化。
