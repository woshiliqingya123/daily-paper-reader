## 摘要
前沿大语言模型（LLMs）能够导航复杂的网站，但其高昂的成本以及对第三方 API 的依赖使得本地部署变得不切实际。我们引入了 Agent-as-Annotators，这是一个通过类比人类标注角色来结构化 Web 智能体合成轨迹生成的框架，利用模块化的 LLM 组件取代了任务设计者（Task Designer）、标注者（Annotator）和监督者（Supervisor）。我们使用 Gemini 3 Pro 作为教师模型，在六个 Web 环境中生成了 3,000 条轨迹，并在通过质量过滤的 2,322 条轨迹

## Abstract
Frontier LLMs can navigate complex websites, but their cost and reliance on third-party APIs make local deployment impractical. We introduce Agent-as-Annotators, a framework that structures synthetic trajectory generation for web agents by analogy to human annotation roles, replacing the Task Designer, Annotator, and Supervisor with modular LLM components. Using Gemini 3 Pro as teacher, we generate 3,000 trajectories across six web environments and fine-tune a 9B-parameter student with pure supervised learning on the 2,322 that pass quality filtering. The resulting model achieves 41.5% on WebArena, surpassing closed-source models such as Claude 3.5 Sonnet (36.0%) and GPT-4o (31.5%) under the same evaluation protocol, and nearly doubling the previous best open-weight result (Go-Browse, 21.7%). Capabilities transfer to unseen environments, with an 18.2 percentage point gain on WorkArena L1 (an enterprise platform never seen during training) and consistent improvements across three additional benchmarks. Ablations confirm that each pipeline component contributes meaningfully, with Judge filtering, evaluation hints, and reasoning traces each accounting for measurable gains. These results demonstrate that structured trajectory synthesis from a single frontier teacher is sufficient to produce competitive, locally deployable web agents. ### 2. 方法论：AGENT-AS-ANNOTATORS 框架
该框架将合成轨迹生成过程类比为人类标注的三个角色，并用模块化的 LLM 组件替换：
*   **任务设计者（Task Designer）**：
    *   **人格生成器（Persona Generator）**：生成多样化的用户背景（如数据科学家、设计师），以诱导产生不同分布的任务。
    *   **任务生成器（Task Generator）**：在真实网页环境中探索，生成具体的任务意图（Intent）和**评估提示（Evaluation Hints）**。提示是该框架的关键，它为后续的监督提供了“特权信息”。
*   **标注者（Annotator）**：
    *   **智能体（Agent）**：仅根据任务意图在重置的环境中执行操作，生成交互轨迹。
*   **监督者（Supervisor）**：
    *   **裁判员（Judge）**：利用执行记录和“评估提示”来验证任务是否成功。只有成功的轨迹会被用于后续的监督微调（SFT）。
*   **关键技术细节**：
    *   **推理轨迹（Reasoning Traces）**：在 SFT 过程中保留教师模型的思考过程（`<thought>` 标签）。
    *   **降低教师推理预算**：研究发现，减少教师模型（Gemini 3 Pro）的思考步数反而能生成更简洁、成功率更高的训练数据。

### 3. 实验设计
*   **训练数据**：在 6 个 WebArena 环境（Reddit, GitLab, 购物等）中生成了 3,000 个任务，最终筛选出 2,322 条成功轨迹（约 1.6 万个步骤）。
*   **基准测试（Benchmarks）**：
    *   **WebArena**：域内测试（环境相同但任务未见）。
    *   **VisualWebArena**：视觉接地任务。
    *   **WorkArena L1/L2**：完全未见的 ServiceNow 企业级平台（跨域泛化）。
    *   **MiniWoB**：原子级网页技能测试。
*   **对比方法**：
    *   **闭源模型**：GPT-4o, Claude 3.5 Sonnet, Gemini 3 Pro。
    *   **开源基座**：Qwen3.5 系列（2B, 4B, 9B, 27B）。
    *   **先前 SFT 最佳**：Go-Browse (7B)。

### 4. 资源与算力
*   **训练算力**：使用了 4 到 8 张 GPU（型号为 **NVIDIA A100 80GB** 或 **H200 141GB**）。
*   **训练时长**：Qwen3.5-9B 模型在 8 张 GPU 上训练 2 个 epoch 大约需要 **12-16 小时**。
*   **推理算力**：使用 vLLM 框架在 2 张 A100/H100 上进行推理评估。

### 5. 实验数量与充分性
*   **实验规模**：涵盖了 5 个主流网页智能体基准测试，总计评估了数千个测试任务。
*   **消融实验**：非常充分。作者分别对**数据规模**（从 285 到 2322 条轨迹）、**裁判过滤**（有无 Judge）、**推理轨迹**（完整、截断或无推理）、**评估提示**（有无 Hints）以及**教师模型质量**进行了详细对比。
*   **客观性**：使用了统一的 BrowserGym 评估协议，确保了与闭源模型对比的公平性。

### 6 主要结论与发现
*   **性能飞跃**：微调后的 9B 模型在 WebArena 上达到 **41.5%**，超越了 GPT-4o (31.5%) 和 Claude 3.5 Sonnet (36.0%)，且几乎是此前开源最佳结果 (21.7%) 的两倍。
*   **强大的泛化性**：在从未见过的企业平台 WorkArena L1 上，性能提升了 **18.2 个百分点**，证明模型学到的是通用的网页交互原语而非简单的环境记忆。
*   **质量胜过数量**：仅需约 2300 条高质量轨迹即可达到顶尖性能，且数据规模呈现对数线性增长，存在边际效应。
*   **推理轨迹至关重要**：移除思考过程会导致性能下降 7.9%，而截断思考过程比完全没有思考过程更糟（导致训练信号不连贯）。

### 7. 优点：亮点与创新
*   **角色类比框架**：将复杂的合成数据生成流程标准化，为后续研究提供了清晰的模块化参考。
*   **评估提示（Hints）的引入**：巧妙地利用教师模型在任务设计阶段的“上帝视角”信息来辅助裁判，显著提升了训练数据的标签准确性。
*   **发现“低推理预算”优势**：打破了“思考越久效果越好”的迷思，指出简洁的推理轨迹更利于学生模型学习。

### 8. 不足与局限
*   **环境覆盖有限**：训练仅基于 6 个 WebArena 环境，虽然展现了泛化性，但尚未在数万个真实网站规模上验证。
*   **裁判偏差风险**：Judge 模块本身也是 LLM，可能存在假阳性（误判成功），且未经过大规模人工校验。
*   **仅限 SFT**：目前仅使用了监督微调，尚未结合强化学习（RL）进行进一步的性能压榨。
*   **人格模块验证不足**：消融实验中对“人格生成器”的独立贡献缺乏完全隔离的对比（如完全随机任务 vs 人格驱动任务）。
