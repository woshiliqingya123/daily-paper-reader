## 摘要
大语言模型（LLMs）在代码生成方面取得了显著进展，但竞赛编程（competitive programming）仍然是一个挑战。最近基于训练的方法通过使用带有执行反馈的强化学习（RL）改进了代码生成。最近的 CURE 框架进一步将测试生成纳入训练过程，在单个模型中联合训练代码编写器（Coder）和测试器（Tester）。在推理阶段，Coder 生成许多候选程序，而 Tester 根据题目描述生成测试用例。通过最多生成测试用例的候选程序被选为最终答案。然而，CURE 存在两个关键局限性：首先，Tester 从不阅读任何候选代码，因此其生成的测试往往无法暴露特定于实现的漏洞（bugs）；其次，Coder 从零开始生成每个候选程序，从未学习过如何根据失败的测试来修复有漏洞的程序。为了解决这些局限性，我们提出了 FixAudit，它从一个新的视角切入竞赛性代码生成：从单个初始候选程序开始，通过有针对性的“测试-修复”调试循环迭代地改进候选程序。该框架通过四个阶段训练一个具有两个专门角色的共享模型：修复器（Fixer），负责根据失败的测试修复当前候选程序；以及审计器（Auditor），负责阅读候选代码以生成能够暴露其剩余漏洞的新测试。我们在 APPS、CodeContests 和 xCodeEval 三个基准测试集上评估了 FixAudit。应用于 7B 模型时，该框架在零样本（zero-shot）设置下超过了同系列中更大的 32B 基线模型的平均性能。与基于相同 7B 基础模型的强基线相比，FixAudit 将平均 Pass@1 提高了 35.1% 至 36.8%，将平均 AvgPassRatio 提高了 7.1% 至 24.5%。

## Abstract
Large language models (LLMs) have made remarkable progress in code generation, but competitive programming remains a challenge. Recent training-based methods have improved code generation by using reinforcement learning (RL) with execution feedback. The more recent framework CURE further incorporates test generation into the training process, jointly training a Coder and a Tester within a single model. At inference time, the Coder generates many candidate programs, and the Tester generates tests from the problem description. The candidate who passes the most of the generated tests is selected as the final answer. However, CURE has two critical limitations. First, the Tester never reads any candidate code, so its tests often fail to expose implementation-specific bugs. Second, the Coder generates every candidate from scratch and never learns to fix a buggy program based on a failed test. To address these limitations, we propose FixAudit, which approaches competitive code generation from a new perspective: starting from a single initial candidate, it iteratively improves the candidate through a targeted test-and-repair debugging cycle. The framework trains one shared model with two specialized roles through four stages: the Fixer, which repairs the current candidate based on a failing test, and the Auditor, which reads the candidate code to generate new tests that expose its remaining bugs. We evaluate FixAudit on three benchmarks: APPS, CodeContests, and xCodeEval. Applied to a 7B model, the framework surpasses the average performance of the larger 32B baseline within the same model family under the zero-shot setting. Compared to strong baselines built on the same 7B base model, FixAudit improves average Pass@1 by 35.1% to 36.8% and average AvgPassRatio by 7.1% to 24.5%.

### 1. 核心问题与研究动机
*   **研究背景**：尽管 LLM 在代码生成上进步巨大，但在逻辑严密的竞赛编程中仍面临挑战。现有的强化学习（RL）框架（如 CURE）存在两个核心局限：
    1.  **盲目测试**：测试生成器（Tester）仅根据题目描述生成用例，不看代码实现，难以发现特定实现中的逻辑漏洞。
    2.  **缺乏修复机制**：代码生成器（Coder）每次都从零开始生成，无法利用失败的测试反馈来针对性地修复现有代码。
*   **核心问题**：如何让模型学会“像程序员一样调试”，即通过分析代码漏洞生成针对性测试，并基于反馈进行局部修复而非全盘重写。

### 2. 方法论：FixAudit 框架
FixAudit 采用“一个模型、两个角色（Fixer 和 Auditor）”的设计，通过四个训练阶段构建闭环：
*   **核心思想**：从初始候选代码出发，通过“审计（发现漏洞）-修复（解决漏洞）”的循环不断迭代。
*   **关键技术细节（四阶段训练）**：
    1.  **阶段 A：执行对齐的监督微调（SFT）**：训练模型预测程序输出（给定代码+输入）和根据规格推导输出（给定题目+输入），建立执行推理能力。
    2.  **阶段 B：修复器强化学习（Round-1 Fixer RL）**：训练模型根据公开测试失败反馈修复代码。引入“不伤害”原则，若修复导致原本通过的测试失败（回归），则奖励为 0。
    3.  **阶段 C：审计器强化学习（Auditor RL）**：训练模型阅读候选代码并生成能暴露其漏洞的测试用例。引入辅助奖励塑形（Reward Shaping），鼓励生成的测试能击败多个错误候选。
    4.  **阶段 D：修复器强化学习（Round-2 Refinement RL）**：利用审计器生成的针对性测试进一步微调修复器，使其能处理深层逻辑错误。
*   **优化算法**：使用 **DAPO**（解耦剪切与动态采样策略优化），相比 GRPO 能更好地处理稀疏奖励，允许模型在发现罕见成功路径时进行更大幅度的更新。

### 6. 主要结论与发现
*   **性能卓越**：基于 Qwen2.5-Coder-7B 的 FixAudit 在平均 Pass@1 上达到了 30.40%，**超越了同系列 32B 模型的零样本表现**（24.33%）。

### 7. 优点与亮点
*   **代码感知审计**：打破了传统测试生成不看代码的局限，使生成的测试具有极强的攻击性和针对性。
*   **局部修复机制**：通过强化学习训练模型进行增量式修改，保留了代码中的正确逻辑，避免了重写带来的新错误。
*   **执行推理对齐**：通过阶段 A 的 SFT 预先注入执行推理能力，解决了 LLM 难以模拟程序运行状态的痛点。

### 8. 不足与局限
*   **语言覆盖**：目前主要针对 Python 语言进行评估，尚未验证在 C++ 或 Java 等其他竞赛常用语言上的泛化性。
*   **训练复杂性**：四阶段训练流程较为复杂，且各阶段是顺序进行的，未来可能需要探索更高效的联合训练（Joint Training）策略。
*   **停止准则**：目前采用固定迭代次数，缺乏一种自适应的机制来决定何时停止修复或何时增加测试。
