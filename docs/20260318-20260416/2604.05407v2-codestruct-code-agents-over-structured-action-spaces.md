## 摘要
基于大语言模型（LLM）的代码智能体通常将代码库视为非结构化文本，通过脆弱的字符串匹配来应用编辑，这种方式常因格式偏移或歧义模式而失效。我们提出将代码库重新构架为结构化动作空间，使智能体在命名的抽象语法树（AST）实体而非文本片段上进行操作。我们的框架 CODESTRUCT 提供了用于检索完整语法单元的 readCode，以及用于对语义程序元素应用经过语法验证的转换的 editCode。在 SWE-Bench Verified 基准测试中，针对六种 LLM 的评估显示，CODESTRUCT 将 Pass@1 准确率提高了 1.2-5.0%，同时使大多数模型的 Token 消耗减少了 12-38%。在基于文本的界面下经常无法生成有效补丁的模型受益最为显著：GPT-5-nano 的准确率提升了 20.8%，其空补丁失败率从 46.6% 降至 7.2%。在 CodeAssistBench 上，我们也观察到一致的准确率提升（+0.8-4.4%）以及高达 33% 的成本降低。研究结果表明，结构感知界面为代码智能体提供了更可靠的基础。

## Abstract
LLM-based code agents treat repositories as unstructured text, applying edits through brittle string matching that frequently fails due to formatting drift or ambiguous patterns. We propose reframing the codebase as a structured action space where agents operate on named AST entities rather than text spans. Our framework, CODESTRUCT, provides readCode for retrieving complete syntactic units and editCode for applying syntax-validated transformations to semantic program elements. Evaluated on SWE-Bench Verified across six LLMs, CODESTRUCT improves Pass@1 accuracy by 1.2-5.0% while reducing token consumption by 12-38% for most models. Models that frequently fail to produce valid patches under text-based interfaces benefit most: GPT-5-nano improves by 20.8% as empty-patch failures drop from 46.6% to 7.2%. On CodeAssistBench, we observe consistent accuracy gains (+0.8-4.4%) with cost reductions up to 33%. Our results show that structure-aware interfaces offer a more reliable foundation for code agents.

### 1. 核心问题与整体含义
*   **研究动机**：现有的 LLM 代码智能体（Code Agents）主要采用“以文本为中心”的范式，将代码库视为扁平的字符序列。它们通过行号或字符串匹配来读取和编辑代码。
*   **核心痛点**：这种方式存在严重的“抽象失配”：
    *   **脆弱性**：微小的格式变化（如空格、缩进）会导致字符串匹配失败。
    *   **低效性**：为了修改几行代码，智能体往往需要重新生成整个函数或文件的文本，浪费大量 Token。
    *   **上下文冗余**：按行读取容易截断语法单元，或引入大量无关代码干扰模型推理。
*   **整体含义**：论文提出将代码库重构为**结构化动作空间**，让智能体直接在抽象语法树（AST）节点（如类、函数、方法）上操作，从而提高代码处理的可靠性和效率。

### 2. 方法论：CODESTRUCT 框架
核心思想是利用 AST 将代码定义为可寻址的命名实体，并提供两个结构感知原语：

*   **`readCode`（结构化检索）**：
    *   **自适应模式**：小文件返回全文；大文件返回结构摘要（仅包含函数/类签名）。
    *   **选择器检索**：智能体通过选择器（如 `User.login`）直接获取特定实体的完整代码块，确保语法完整性，避免无关上下文。
*   **`editCode`（结构化修改）**：
    *   **原子操作**：支持 `insert`（插入）、`replace`（替换）和 `removal`（删除）。
    *   **语法验证**：在应用修改前，工具会自动验证修改后的 AST 是否符合语法规范。如果产生语法错误，则拒绝修改并报错，引导智能体自我修正。
    *   **格式保持**：自动处理缩进和上下文对齐，无需智能体手动管理格式。

### 6. 主要结论与发现
*   **性能提升**：在 SWE-Bench Verified 上，CODESTRUCT 将 Pass@1 准确率提升了 **1.2%–5.0%**。
*   **成本降低**：大多数模型的 Token 消耗减少了 **12%–38%**，推理成本最高降低了 **33%**。
*   **小模型受益最大**：GPT-5-nano 的准确率大幅提升了 **20.8%**。这表明结构化接口能显著弥补小模型在处理复杂文本格式时的脆弱性。
*   **可靠性增强**：显著减少了“空补丁（Empty Patch）”失败的情况，使智能体能够更专注于逻辑推理而非文本对齐。

### 7. 优点与亮点
*   **解决根本矛盾**：直接针对代码的结构化本质设计动作空间，消除了文本匹配的固有缺陷。
*   **即插即用**：通过模型上下文协议（MCP）实现，无需对 LLM 进行微调，即可集成到现有智能体框架中。
*   **语法护栏**：内置的语法验证机制为智能体提供了“安全网”，大幅降低了生成无效代码的概率。

### 8. 不足与局限
*   **跨文件分析缺失**：目前仅支持单文件内的 AST 操作，尚未建模跨文件的继承关系或调用图（Call Graph）。
*   **语法依赖性**：要求源文件本身必须是语法正确的。如果代码库中存在已有语法错误的文件，AST 解析将失效。
*   **语言覆盖**：虽然在 CodeAssistBench 测试了多语言，但核心的 bug 修复评估（SWE-Bench）仍集中在 Python 上，对于静态强类型语言（如 Java/C++）的复杂泛型等特性的处理能力有待进一步验证。
