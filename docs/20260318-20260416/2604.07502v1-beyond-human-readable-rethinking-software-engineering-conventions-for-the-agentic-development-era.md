## 摘要
六十年来，软件工程原则一直针对单一消费者——人类开发者进行优化。随着智能体 AI 开发（Agentic AI development）的兴起，基于大语言模型（LLM）的智能体能够自主阅读、编写、导航和调试代码库，这引入了一个具有根本不同约束条件的新型主要消费者。本文对智能体压力下的以人为中心的规范进行了系统分析，并提出了一项关键设计原则：语义密度优化（semantic density optimization），即在保留高语义价值 Token 的同时，消除不含信息的 Token。我们通过一项针对四种条件（人类可读、结构化、压缩和工具辅助压缩）下日志格式 Token 经济性的受控实验验证了这一原则，并展示了一个反直觉的发现：尽管激进的压缩减少了 17% 的输入 Token，但由于它将解释负担转移到了模型的推理阶段，导致总会话成本增加了 67%。我们扩展了这一原则，提议重新启用经典的反模式（anti-patterns），引入了用于智能体代码导航的程序骨架（program skeleton）概念，并主张将语义意图与人类可读的表示形式进行根本性的解耦。

## Abstract
For six decades, software engineering principles have been optimized for a single consumer: the human developer. The rise of agentic AI development, where LLM-based agents autonomously read, write, navigate, and debug codebases, introduces a new primary consumer with fundamentally different constraints. This paper presents a systematic analysis of human-centric conventions under agentic pressure and proposes a key design principle: semantic density optimization, eliminating tokens that carry zero information while preserving tokens that carry high semantic value. We validate this principle through a controlled experiment on log format token economy across four conditions (human-readable, structured, compressed, and tool-assisted compressed), demonstrating a counterintuitive finding: aggressive compression increased total session cost by 67% despite reducing input tokens by 17%, because it shifted interpretive burden to the model's reasoning phase. We extend this principle to propose the rehabilitation of classical anti-patterns, introduce the program skeleton concept for agentic code navigation, and argue for a fundamental decoupling of semantic intent from human-readable representation.

    *   挑战传统的“小文件”原则。在智能体看来，将逻辑分散在15个文件（多次工具调用、重复样板）的成本远高于一个800行的“上帝对象”（单次读取、上下文连贯）。

### 6. 主要结论与发现
*   **压缩悖论（Compression Paradox）**：激进的压缩（格式C）虽然减少了17%的输入Token，但导致总会话成本增加了 **67%**。
*   **推理税（Reasoning Tax）**：压缩语义信息会将解释负担转移到模型的推理阶段，导致模型需要消耗更多Token来“自言自语”地解码缩写，从而抵消了输入侧的节省。
*   **语义密度胜过Token最小化**：最优的表示形式是“语义密集”的。良好的命名和清晰的结构对人类和AI都有利，真正的浪费在于那些为了满足框架或语言严谨性而存在的“零信息”结构化代码。

### 7. 优点
*   **视角独特**：首次系统性地挑战了“人类可读即最优”的软件工程假设。
*   **实证发现反直觉**：通过实验证明了简单的Token压缩在Agent工作流中可能适得其反，提出了“推理税”这一重要概念。
*   **实用建议**：提出的“程序骨架”和“语义意图与表示解耦”具有很强的工程落地指导意义。

### 8. 不足与局限
*   **训练分布偏差（Distributional Drift）**：LLM 是在大量遵循传统规范（如SOLID）的代码上训练的。如果代码库过度偏离这些规范（如使用上帝对象），可能会导致模型性能下降或幻觉增加。
*   **注意力衰减**：大文件虽然减少了工具调用，但可能触发 LLM 的“迷失在中间”（Lost in the Middle）现象，影响信息提取精度。
*   **人类审查成本**：过度为智能体优化的代码（如极长文件、取消抽象层）会增加人类进行代码审查（Code Review）的认知负担。
*   **实验覆盖面**：目前的定量实验仅限于日志分析，尚未对大规模代码重构和复杂系统架构进行定量验证。
