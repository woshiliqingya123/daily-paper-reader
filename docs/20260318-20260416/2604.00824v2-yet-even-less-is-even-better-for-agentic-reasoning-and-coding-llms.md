## 摘要
训练有效的软件工程智能体需要大量的特定任务轨迹，这导致了高昂的数据构建成本。受数学推理中“少即是多”（Less-Is-More）假设的启发，我们研究了其在智能体场景中的扩展，并提出了一种端到端训练框架，通过更少但更高质量的训练轨迹实现了卓越的智能体能力。这是通过 STITCH（滑动记忆轨迹推理与任务分块启发式）实现的，这是一种由粗到精的机制，能够过滤低价值噪声并保留关键决策 token，从而最大化训练信号的质量。我们在多个智能体框架（如 mini-SWE-agent、MSWE-agent）、模型规模（30B 到 355B）以及多语言设置（Python、Java 和 ArkTS）上进行了实验。在 SWE-bench Verified 上，使用 STITCH 训练的模型相比基础模型实现了高达 63.16% 的相对提升。在 Multi-SWE-bench (Java) 上，MiniMax-M2.5-STITCH 配合我们的 CodeArts Agent 脚手架达到了 43.75%（+16.67%）。在鸿蒙系统（ArkTS）上，GLM-4.7-STITCH 仅使用不到 1000 条训练轨迹，就将编译通过率提高到了 61.31%（+43.34%）。我们的结果证实，“少即是多”范式可以有效地推广到跨多种语言和模型规模的复杂智能体任务中。

## Abstract
Training effective software engineering agents requires large volumes of task-specific trajectories, incurring substantial data construction costs. Inspired by the "Less-Is-More" hypothesis in mathematical reasoning, we investigate its extension to agentic scenarios and propose an end-to-end training framework that achieves superior agentic capabilities with fewer but higher-quality training trajectories. This is achieved via STITCH (Sliding-memory Trajectory Inference and Task Chunking Heuristic), a coarse-to-fine mechanism that filters low-value noise and retains decision-critical tokens to maximize training signal quality. We conduct experiments across multiple agent frameworks (e.g., mini-SWE-agent, MSWE-agent), model scales (30B to 355B), and multilingual settings (Python, Java, and ArkTS). On SWE-bench Verified, models trained with STITCH achieve up to 63.16% relative improvement over base models. On Multi-SWE-bench (Java), MiniMax-M2.5-STITCH achieves 43.75% with our CodeArts Agent scaffold (+16.67%). On HarmonyOS (ArkTS), GLM-4.7-STITCH improves the compilation pass rate to 61.31% (+43.34%) with less than 1K training trajectories. Our results confirm that the "Less-Is-More" paradigm generalizes effectively to complex agentic tasks across diverse languages and model scales.

*   **研究动机**：构建有效的软件工程智能体通常需要海量的任务轨迹数据，这带来了极高的数据构建成本和标注负担。
*   **核心问题**：受数学推理领域“少即是多”（Less-Is-More, LIMO）假设的启发，作者探索该假设是否能扩展到复杂的智能体、推理和编程场景。
*   **整体含义**：论文旨在证明，通过精细的数据清洗和关键决策片段提取，使用极少量的（如不到 1000 条）高质量轨迹数据，就能显著提升大模型在复杂软件修复任务中的表现。

### 2. 论文提出的方法论
论文提出了一个端到端的训练框架，包含两个核心组件：
*   **SandForge（数据构建与评估框架）**：
    *   将真实的 GitHub Issue 转化为可执行的任务。
    *   自动验证任务的有效性（如：复现 Bug 的测试用例必须失败，修复后的代码必须通过测试）。
    *   统一管理环境配置、智能体执行轨迹、奖励信号和补丁生成。
*   **STITCH（由粗到精的轨迹数据精选机制）**：
    *   **宏观预筛选（Macro-Level）**：利用逻辑回归（LR）模型，基于统计特征（如代码产量、工具调用成功率、交互轮数、Token 消耗等）快速过滤掉低质量或无效的轨迹。
    *   **微观语义提取（Micro-Level）**：针对长轨迹，采用 **Map-Reduce 范式结合滑动记忆机制**。
        *   **Map 阶段**：将长轨迹切分为语义完整的块（Chunk），利用 LLM 作为裁判进行评分，并通过滑动记忆保留上下文连贯性。
        *   **Reduce 阶段**：汇总各块评分，识别并提取出即使在失败轨迹中也存在的“高价值决策片段”。
    *   **核心思想**：过滤噪声，只保留对决策至关重要的 Token 进行训练。

### 5. 实验数量与充分性
*   **实验规模**：论文在三种编程语言、多个模型参数量级（30B, 100B, 200B+）以及多个智能体脚手架（mini-SWE-agent, CodeArts-Agent 等）上进行了广泛实验。
*   **充分性**：实验设计较为充分，不仅验证了性能提升，还通过 ArkTS 案例展示了模型在处理低资源语言和严格类型系统时的改进。

### 6. 主要结论与发现
*   **“少即是多”范式有效**：在智能体场景下，高质量的精简数据优于大规模噪声数据。
*   **显著提升**：在 Python 场景下，30B 模型相对提升达 63.16%；在 Java 场景下，MiniMax-M2.5 达到 SOTA 水平（43.75%）；在 ArkTS 场景下，仅用约 1000 条数据就将编译通过率提升了 43.34%。
*   **片段提取的价值**：STITCH 能够从全局失败的轨迹中提取局部成功的正确决策片段，极大提高了数据利用率。

### 7. 优点
*   **数据效率极高**：挑战了“大数据”迷思，为资源受限的团队提供了训练高性能智能体的路径。
*   **长轨迹处理创新**：STITCH 的滑动记忆 Map-Reduce 机制有效解决了 LLM 裁判处理超长上下文时的语义断裂问题。
*   **多语言泛化**：证明了该方法在主流语言（Python/Java）和新兴语言（ArkTS）上均具有强鲁棒性。

### 8. 不足与局限
*   **SOTA 模型边际效应**：在超过 200B 的顶级模型上，STITCH 带来的提升相对较小，可能因为这些模型在预训练阶段已接近该基准测试的性能天花板。
*   **依赖 LLM 裁判**：微观筛选阶段高度依赖高性能 LLM（如 Qwen3.5-122B）作为裁判，这本身也存在一定的计算开销和潜在的偏见风险。
*   **应用限制**：虽然在软件修复上表现优异，但在更开放、缺乏明确验证器（Verifier）的智能体任务中，该框架的自动化程度可能会受限。
