## 摘要
AI 智能体作为自主数字参与者，需要智能体原生协议。现有方法（如 GUI 自动化和基于 MCP 的技能）由于缺乏统一的顶层框架和关键组件，且各独立模块存在缺陷，导致 Token 消耗高、交互碎片化、安全性不足。为解决这些问题，我们提出了 ANX，这是一种开放、可扩展、可验证的智能体原生协议和顶层框架，集成了 CLI、Skill 和 MCP，通过协议创新、架构优化和工具补充解决了上述痛点。其四大核心创新包括：1) 智能体原生设计（ANX Config、Markup、CLI），具有高信息密度、灵活性和强适应性，可减少 Token 消耗并消除不一致性；2) 人机交互结合了 Skill 的灵活性，可实现智能体可执行指令和人类可读 UI 的双重渲染；3) 支持 MCP 的按需轻量级应用，无需预注册；4) 基于 ANX Markup 的机器可执行 SOP，消除了歧义，确保了长程任务和多智能体协作的可靠性。作为系列研究的第一篇，我们重点介绍了 ANX 的设计，展示了其包含 ANXHub 的 3EX 解耦架构，并进行了初步的可行性分析和实验验证。ANX 确保了原生安全性：绕过大语言模型（LLM）的 UI 到核心（UI-to-Core）通信使敏感数据脱离智能体上下文；仅限人工确认的机制防止了自动化滥用。使用 Qwen3.5-plus/GPT-4o 进行的表单填写实验表明，与基于 MCP 的技能相比，ANX 分别减少了 47.3% (Qwen3.5-plus) 和 55.6% (GPT-4o) 的 Token 消耗；与 GUI 自动化相比，分别减少了 57.1% (Qwen3.5-plus) 和 66.3% (GPT-4o) 的 Token 消耗；且执行时间比基于 MCP 的技能缩短了 58.1% 和 57.7%。

## Abstract
AI agents, autonomous digital actors, need agent-native protocols; existing methods include GUI automation and MCP-based skills, with defects of high token consumption, fragmented interaction, inadequate security, due to lacking a unified top-level framework and key components, each independent module flawed. To address these issues, we present ANX, an open, extensible, verifiable agent-native protocol and top-level framework integrating CLI, Skill, MCP, resolving pain points via protocol innovation, architectural optimization and tool supplementation. Its four core innovations: 1) Agent-native design (ANX Config, Markup, CLI) with high information density, flexibility and strong adaptability to reduce tokens and eliminate inconsistencies; 2) Human-agent interaction combining Skill's flexibility for dual rendering as agent-executable instructions and human-readable UI; 3) MCP-supported on-demand lightweight apps without pre-registration; 4) ANX Markup-enabled machine-executable SOPs eliminating ambiguity for reliable long-horizon tasks and multi-agent collaboration. As the first in a series, we focus on ANX's design, present its 3EX decoupled architecture with ANXHub and preliminary feasibility analysis and experimental validation. ANX ensures native security: LLM-bypassed UI-to-Core communication keeps sensitive data out of agent context; human-only confirmation prevents automated misuse. Form-filling experiments with Qwen3.5-plus/GPT-4o show ANX reduces tokens by 47.3% (Qwen3.5-plus) and 55.6% (GPT-4o) vs MCP-based skills, 57.1% (Qwen3.5-plus) and 66.3% (GPT-4o) vs GUI automation, and shortens execution time by 58.1% and 57.7% vs MCP-based skills.

*   **MCP（模型上下文协议）：** 虽有改进，但存在预安装门槛、无法“即用即走”、交互碎片化以及敏感数据必须经过 LLM 上下文导致的隐私泄露风险。

**ANX 的核心目标**是提出一种“协议优先”的智能体原生交互框架，通过统一的顶层设计解决效率、安全、协作和语义精准度四大痛点。

### 2. 方法论：核心思想与关键技术
论文提出了 **ANX 协议** 及其配套的 **3EX 解耦架构**：

*   **3EX 架构（Expression-Exchange-Execution）：**
    *   **表达层（Expression）：** 使用 **ANX Markup**（一种高信息密度的结构化编码）定义任务元数据、校验规则和安全注释。
    *   **交换层（Exchange）：** 通过 **ANXHub** 实现。它是一个全球化的应用市场，支持语义向量搜索，Agent 可按需发现并调用工具，无需预装。
    *   **执行层（Execution）：** 由 **ANX Core** 将指令编译为轻量级的 **ANX CLI** 命令，并在 **ANX Node**（执行容器）中运行。
*   **关键技术细节：**
    *   **UI-to-Core 直接通信：** 当涉及敏感数据（如密码）时，ANX UI 直接与 Core 通信，LLM 仅获得引用 Token，从而实现数据隔离，防止隐私泄露。
    *   **双重渲染：** 同一套 ANX 定义既能渲染为 Agent 可读的指令，也能渲染为人类可操作的 UI（H5/小程序）。
    *   **机器可执行 SOP：** 利用 ANX Markup 的结构化语义（sources/targets 机制）定义确定性的状态机，消除自然语言歧义。

### 6. 主要结论与发现
*   **Token 效率显著提升：** 相比 MCP，ANX 减少了 **47.3% - 55.6%** 的增量 Token 消耗；相比 GUI 自动化，减少了 **57.1% - 66.3%**。
*   **执行速度大幅加快：** ANX 的执行时间比 MCP 缩短了约 **58%**，比 GUI 缩短了约 **61% - 65%**。
*   **核心发现：** 效率提升的关键在于“渐进式披露”和“执行层解析”。ANX 将动态数据（如远程下拉列表）的解析从 LLM 上下文转移到了执行层（Core），避免了 Token 爆炸。
*   **安全性验证：** 成功实现了敏感数据绕过 LLM 的传输路径，并证明了“仅限人工确认”状态机在防止自动化滥用方面的可行性。

### 7. 优点（亮点）
*   **协议原生性：** 摆脱了“模拟人类”的思路，为 Agent 量身定制了高密度、结构化的交互语言。
*   **隐私保护设计：** UI-to-Core 机制从架构层面解决了 LLM 隐私泄露的顽疾，具有极高的工业应用价值。
*   **解耦架构：** 3EX 架构实现了表达、交换、执行的分离，使得 Agent 能够像人类使用 App Store 一样“即用即走”。
*   **SOP 确定性：** 将复杂的 SOP 转化为机器可执行的状态机，为多智能体协作提供了稳定的底座。

### 8. 不足与局限
*   **实验场景单一：** 目前仅验证了表单填写任务，尚未在更复杂的长程多步任务（如 50 步以上的嵌套分支）中进行大规模量化。
*   **依赖中心化组件：** ANXHub 的引入虽然方便了发现，但也带来了对中心化节点的信任依赖（论文在未来工作中提到了弱中心化方案）。
*   **安全边界限制：** 协议无法防御 LLM 诱导的社会工程学攻击（如 LLM 诱导用户手动发送敏感信息）。
*   **生态门槛：** 作为一个新协议，需要开发者重新编写 ANX Markup，存在一定的迁移和学习成本。
