## 摘要
基于大语言模型（LLM）驱动的网页智能体通过持续推理循环运行——即重复查询模型以评估浏览器状态并选择操作——在处理重复性任务时表现出根本性的可扩展性限制。我们将此特征描述为“重复运行危机”（Rerun Crisis）：Token 消耗和 API 延迟随执行频率呈线性增长。对于一个包含 5 个步骤且迭代 500 次的工作流，持续推理型智能体会产生约 150.00 美元的推理成本；即使采用激进的缓存策略，成本仍接近 15.00 美元。我们提出了一种“编译并执行”（Compile-and-Execute）架构，将 LLM 推理与浏览器执行解耦，将单个工作流的推理成本降低至 0.10 美元以下。通过单次 LLM 调用处理来自 DOM 清洗模块（DSM）的高 Token 效率语义表示，并生成确定性的 JSON 工作流蓝图。随后，轻量级运行时在无需进一步模型查询的情况下驱动浏览器。我们将这种成本降低形式化为从 O(M x N) 到摊销 O(1) 的推理扩展，其中 M 是重复运行次数，N 是顺序操作数。在数据提取、表单填写和指纹识别任务中的实证评估显示，零样本编译成功率达到 80-94%。关键在于，JSON 中间表示的模块化允许通过极少的人机回环（HITL）修补，将执行可靠性提升至接近 100%。在五种前沿模型上，单次编译成本仅在 0.002 美元至 0.092 美元之间，这些结果证明了确定性编译作为一种范式，能够实现在此前持续推理架构下经济上不可行的大规模自动化。

## Abstract
LLM-driven web agents operating through continuous inference loops -- repeatedly querying a model to evaluate browser state and select actions -- exhibit a fundamental scalability constraint for repetitive tasks. We characterize this as the Rerun Crisis: the linear growth of token expenditure and API latency relative to execution frequency. For a 5-step workflow over 500 iterations, a continuous agent incurs approximately 150.00 USD in inference costs; even with aggressive caching, this remains near 15.00 USD. We propose a Compile-and-Execute architecture that decouples LLM reasoning from browser execution, reducing per-workflow inference cost to under 0.10 USD. A one-shot LLM invocation processes a token-efficient semantic representation from a DOM Sanitization Module (DSM) and emits a deterministic JSON workflow blueprint. A lightweight runtime then drives the browser without further model queries. We formalize this cost reduction from O(M x N) to amortized O(1) inference scaling, where M is the number of reruns and N is the sequential actions. Empirical evaluation across data extraction, form filling, and fingerprinting tasks yields zero-shot compilation success rates of 80-94%. Crucially, the modularity of the JSON intermediate representation allows minimal Human-in-the-Loop (HITL) patching to elevate execution reliability to near-100%. At per-compilation costs between 0.002 USD and 0.092 USD across five frontier models, these results establish deterministic compilation as a paradigm enabling economically viable automation at scales previously infeasible under continuous architectures.

### 1. 核心问题与研究动机
*   **核心问题：** 论文识别并定义了**“重运行危机”（Rerun Crisis）**。目前的网页智能体（如 ReAct 框架）通常采用“连续推理循环”，即每执行一个动作都要调用一次 LLM。在处理大规模重复性任务（如抓取 500 个页面）时，推理成本和延迟会随执行次数（M）和步骤数（N）线性增长（复杂度为 $O(M \times N)$），导致企业级应用在经济上不可行。
*   **研究背景：** 尽管模型能力在提升，但 API 调用成本依然高昂。一个简单的 5 步工作流重复 500 次，成本可能高达 150 美元，这限制了 LLM 智能体从原型走向生产环境。

### 2. 方法论
*   **核心思想：** 借鉴编译器原理，将 LLM 的“推理”与浏览器的“执行”解耦。将 LLM 视为**编译器**，将用户意图编译成一个确定性的 **JSON 工作流蓝图（中间表示，IR）**，然后由轻量级运行时（Runtime）独立执行，无需再次调用 LLM。
*   **关键技术细节：**
    *   **DOM 清洗模块 (DSM)：** 在编译前对原始 HTML 进行压缩，剔除脚本、样式、不可见元素及冗余属性，将 Token 消耗降低高达 85%，并强制模型关注语义化选择器（如 ARIA 角色、data-* 属性）。
    *   **一次性编译 (One-Shot Compilation)：** LLM 接收清洗后的 DOM 和用户意图，一次性生成包含所有逻辑（包括翻页、循环、提取字段）的 JSON 蓝图。
    *   **确定性执行引擎：** 运行时根据 JSON 蓝图驱动浏览器，采用动态等待启发式算法处理异步渲染（SPA）。
    *   **延迟重规划 (Lazy Replanning)：** 仅在执行失败（如 UI 变动导致选择器失效）时才触发 LLM 进行“选择器修复”，而非重新运行整个推理循环。
*   **公式化表达：** 将推理成本从 $Cost \approx M \times \sum (S_i \times C_t)$ 降低到摊销后的 $O(1)$ 复杂度，即 $Cost \approx 1 \times (S_{compile} \times C_t)$。

### 3. 实验设计
*   **任务场景：** 评估了三种企业级任务：
    1.  **大规模翻页提取：** 提取 10 页共 300 个商业档案。
    2.  **表单填写：** 处理复杂的非标准输入和下拉菜单。
    3.  **技术栈指纹识别：** 导航并分析网站部署的技术（CMS、分析工具等）。
*   **对比基准 (Benchmark)：** 理论上对比了“连续推理智能体”与“优化后的缓存智能体”，实证上测试了五种前沿模型（Claude 3 Opus/Sonnet, GPT-5.2-Codex, Qwen 3.5/3 Coder 等）的编译表现。
*   **评估指标：** 编译成功率（语法正确性）和执行准确率（最终状态正确性）。

### 4. 资源与算力
*   **算力说明：** 论文未提及模型训练所需的 GPU 资源，因为该研究是基于现有的前沿模型 API（通过 OpenRouter 接入）进行的系统架构创新。
*   **推理成本记录：** 详细记录了不同模型的 API 支出，单次编译成本在 **0.002 美元至 0.092 美元**之间。

### 5. 实验数量与充分性
*   **实验规模：** 针对提取和指纹识别任务各进行了 50 次独立编译尝试，针对复杂的表单填写进行了 10 次尝试。
*   **充分性评价：** 实验覆盖了主流的网页交互模式。虽然样本量在统计学上不算巨大，但通过跨多个前沿模型的对比，证明了该架构在当前最强 LLM 上的普适性。不过，由于使用了私有的企业级 DOM 数据，外部独立复现存在一定难度。

### 6. 主要结论与发现
*   **成本大幅降低：** 相比于传统的连续推理架构，该方法将推理成本降低了约 **1500 倍**。
*   **高成功率：** 零样本（Zero-shot）编译成功率在 80% 到 94% 之间。
*   **人机协作价值：** 由于 JSON 蓝图是结构化且可读的，通过极少的人工干预（HITL）即可将执行可靠性提升至接近 100%。
*   **模型差异：** 较小的模型（如 Gemini Flash 或 Claude Haiku）在处理复杂 Schema 生成时表现较差，而 Claude Opus 和 Qwen Coder 表现优异。

### 7. 优点
*   **经济性极佳：** 真正解决了 LLM 智能体在重复性任务中“用不起”的问题。
*   **鲁棒性设计：** DSM 模块通过强制语义选择器，使生成的脚本比传统的 CSS/XPath 脚本更具抗干扰能力。
*   **安全性与可控性：** JSON 蓝图在执行前可被人类审计，避免了连续推理智能体可能出现的“逻辑漂移”或不可预测的破坏性操作。

### 8. 不足与局限
*   **应用限制：** 依赖于 DOM 结构。对于 Canvas 渲染、WebGL 或高度混淆的无 DOM 界面（如某些复杂游戏或高度加密页面），该架构失效，仍需依赖基于视觉的 VLM 智能体。
*   **UI 波动风险：** 虽然语义选择器有一定韧性，但如果网页发生重大改版，仍需重新编译。
*   **偏差风险：** 实验主要基于标准 HTML 结构的商业网站，对于结构极度不规范的“野路子”网站，编译成功率可能会显著下降。
