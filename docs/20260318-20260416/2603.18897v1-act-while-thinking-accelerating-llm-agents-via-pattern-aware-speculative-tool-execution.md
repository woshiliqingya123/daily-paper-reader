## 摘要
以大语言模型（LLM）驱动的智能体正成为自主任务解决的主流范式。与标准的推理负载不同，智能体运行在严格串行的“LLM-工具”循环中，LLM 在每一步都必须等待外部工具的执行。这种执行模型引入了严重的延迟瓶颈。为解决这一问题，我们提出了 PASTE，一种模式感知的投机性工具执行方法，旨在通过投机执行来隐藏工具延迟。PASTE 基于以下洞察：尽管智能体请求在语义上具有多样性，但它们表现出稳定的应用级控制流（重复出现的工具调用序列）和可预测的数据依赖关系（工具间的参数传递）。通过利用这些特性，PASTE 通过投机性工具执行提升了智能体的服务性能。与最先进的基准方法相比，实验结果表明 PASTE 将平均任务完成时间缩短了 48.5%，并将工具执行吞吐量提高了 1.8 倍。

## Abstract
LLM-powered agents are emerging as a dominant paradigm for autonomous task solving. Unlike standard inference workloads, agents operate in a strictly serial "LLM-tool" loop, where the LLM must wait for external tool execution at every step. This execution model introduces severe latency bottlenecks. To address this problem, we propose PASTE, a Pattern-Aware Speculative Tool Execution method designed to hide tool latency through speculation. PASTE is based on the insight that although agent requests are semantically diverse, they exhibit stable application level control flows (recurring tool-call sequences) and predictable data dependencies (parameter passing between tools). By exploiting these properties, PASTE improves agent serving performance through speculative tool execution. Experimental results against state of the art baselines show that PASTE reduces average task completion time by 48.5% and improves tool execution throughput by 1.8x.

### 2. 方法论：核心思想与关键技术
PASTE 的核心思想是利用智能体行为的**模式规律性**（稳定的控制流和可预测的数据流）来预测未来的工具调用。

*   **模式元组（Pattern Tuple）：** 定义为 `(context, prediction, function, probability)`。
    *   **Context (C):** 历史工具调用的签名序列（不含具体参数），用于识别稳定的控制流。
    *   **Prediction (T):** 预测下一个可能调用的工具类型。
    *   **Function (f):** 符号化值映射函数，用于从历史输出中提取参数（如从搜索结果 JSON 中提取第一个 URL），解决参数预测难题。
    *   **Probability (p):** 基于历史数据的置信度。
*   **两阶段模式挖掘：** 
    1.  **结构挖掘：** 从历史轨迹中提取频繁出现的工具调用序列。
    2.  **依赖推断：** 识别参数是如何在工具间传递的（如生产者-消费者关系）。
*   **机会主义调度器（Opportunistic Scheduler）：**
    *   **优先级划分：** 将任务分为“权威调用”（Agent 真实发出的）和“投机调用”（系统预测的）。
    *   **资源隔离：** 投机任务仅利用系统空闲资源（Slack Resources）运行，一旦发生资源竞争，立即抢占（Preempt）投机任务。
    *   **晋升机制：** 如果 Agent 随后发出的真实请求与正在运行的投机任务匹配，则将其“晋升”为权威任务，直接复用结果。

*   **解耦设计：** 通过“模式元组”将控制流与数据流分离，解决了 Agent 请求高度非确定性带来的预测难题。
*   **符号化参数推断：** 不依赖 LLM 预测参数（避免幻觉和高延迟），而是通过符号函数从上下文提取，极具创新性。
*   **风险可控：** 引入了副作用策略（Speculation Eligibility Policy），支持“干跑（Dry-run）”或重定向到暂存资源，确保了投机执行的安全性。
*   **资源高效：** 采用机会主义调度，只在资源空闲时“捡漏”，不影响正常推理任务。

### 8. 不足与局限
*   **依赖历史数据：** 模式挖掘需要一定数量的历史执行轨迹，对于完全新颖、无规律的任务，加速效果有限。
*   **副作用限制：** 对于某些具有不可逆外部影响（如发送邮件、支付）且无法通过策略重写的工具，系统无法进行投机执行。
*   **资源浪费风险：** 虽然使用了空闲资源，但在预测错误时仍会产生额外的电力和网络带宽消耗。
*   **应用范围：** 主要针对工具密集型（Tool-heavy）任务，对于纯逻辑推理、极少调用工具的任务提升不明显。
