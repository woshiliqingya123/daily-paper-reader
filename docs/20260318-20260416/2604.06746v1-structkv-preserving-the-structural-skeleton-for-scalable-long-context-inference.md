## 摘要
随着大语言模型（LLMs）扩展到支持超过一百万个 token 的上下文窗口，键值（KV）缓存的线性增长带来了严重的显存容量和带宽瓶颈，限制了长上下文推理的效率。现有的压缩方法通常根据局部显著性指标对 token 进行优先级排序，以将预填充计算与解码内存解耦。然而，这些方法往往依赖于特定层的局部显著性快照，从而系统性地丢弃了那些在整个网络深度中充当全局信息枢纽、但在选定的剪枝特定层中暂时处于休眠状态的 token。为了解决这一局限性，我们提出了 StructKV，这是一个结构感知的 KV 缓存压缩框架，它引入了三项核心创新：首先，全局入度中心性（Global In-Degree Centrality）通过聚合整个网络深度的注意力模式来识别全局信息枢纽；其次，动态枢轴检测（Dynamic Pivot Detection）利用信息论指标自适应地定位压缩的最佳层；最后，结构传播与解耦（Structural Propagation and Decoupling）将计算预算与内存存储预算分离。在 LongBench 和 RULER 基准测试上的实验结果表明，StructKV 有效地保留了长程依赖关系和检索鲁棒性。

## Abstract
As Large Language Models (LLMs) scale to support context windows exceeding one million tokens, the linear growth of Key-Value (KV) cache imposes severe memory capacity and bandwidth bottlenecks, constraining the efficiency of long-context inference. Existing compression approaches typically prioritize tokens based on local saliency metrics to decouple prefill computation from decoding memory. However, these methods often rely on local saliency snapshots at a specific layer, thereby systematically discarding tokens that act as global information hubs across the network depth but appear temporarily dormant at the specific layer selected for pruning. To address this limitation, we propose StructKV, a structure-aware KV cache compression framework that introduces three core innovations: First, Global In-Degree Centrality aggregates attention patterns across the network depth to identify global information hubs. Second, Dynamic Pivot Detection utilizes information-theoretic metrics to adaptively locate the optimal layer for compression. Finally, Structural Propagation and Decoupling separates the computational budget from the memory storage budget. Experimental results on the LongBench and RULER benchmarks demonstrate that StructKV effectively preserves long-range dependencies and retrieval robustness.

#### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）支持的上下文窗口突破百万级别，**KV Cache（键值缓存）** 的线性增长成为了推理效率的致命瓶颈，主要表现为显存占用过高和内存带宽受限。
*   **现有局限性**：目前的压缩方法（如 SnapKV、FastKV）大多依赖“局部显著性快照”，即根据某一特定层的注意力分数来决定丢弃哪些 Token。
*   **研究动机**：作者发现这种“近视”的方法存在风险——某些 Token 在特定层可能看起来“休眠”（注意力权重低），但在整个网络的语义流中却充当着全局“信息枢纽”或结构骨架的作用。一旦被误删，会导致长程依赖和复杂推理能力的不可逆损失。

#### 2. 方法论：核心思想与技术细节
StructKV 提出了一种结构感知的压缩框架，核心思想是通过全局视角识别并保留文本的“结构骨架”。其包含三个关键技术：
*   **全局入度中心性（Global In-Degree Centrality）**：
    *   不再依赖单层快照，而是通过递归方式累积从输入层到“枢轴层（Pivot Layer）”的所有注意力分数。
    *   引入层级衰减因子 $\lambda$，使模型能平衡早期结构信息与深层语义信息，从而识别出在多层中持续贡献的“信息枢纽”Token。
*   **动态枢轴检测（Dynamic Pivot Detection）**：
    *   **核心逻辑**：自动寻找注意力机制从“广泛探索”转向“聚焦提取”的相位转换点。
    *   **指标**：实时监控注意力熵（Entropy）、稀疏度（Sparsity）和方差（Variance）的梯度变化。当这些指标趋于稳定时，自动触发压缩操作，避免了人工设定固定剪枝层的盲目性。
*   **结构传播与解耦（Structural Propagation & Decoupling）**：
    *   **计算与存储分离**：在预填充（Prefill）阶段，使用较高的保留率（$R_{struct}$）来维持计算精度；在解码（Decoding）阶段，使用更严格的预算（$R_{KV}$）来压缩显存。
    *   通过重新对齐位置 ID（Position IDs）确保旋转位置编码（RoPE）的一致性。

#### 3. 实验设计
*   **模型架构**：涵盖了 LLaMA-3.1-8B-Instruct、Ministral-8B-Instruct 以及 Qwen-2.5 全系列（7B、14B、32B），验证了跨架构和跨规模的泛化性。
*   **基准测试（Benchmarks）**：
    *   **LongBench**：包含 16 个子任务（摘要、单/多文档问答、代码完成等）。
    *   **RULER**：测试 8K 到 128K 长度下的有效上下文保留能力。

*   **对比方法**：
    *   解码端压缩：StreamingLLM, H2O, SnapKV。
    *   预填充感知压缩：PyramidInfer, GemFilter, FastKV（当时的 SOTA）。

#### 4. 资源与算力
*   **硬件环境**：所有实验均在单张 **NVIDIA A800 GPU (80GB)** 上运行。
*   **软件框架**：基于 Hugging Face Transformers 和 FlashAttention-2 实现。
*   **开销分析**：论文明确指出，StructKV 引入的额外组件（全局分数累加器和动态检测器）在 32K 上下文下的延迟开销仅为约 35ms，占总预填充延迟的比例不足 2.5%，而整体预填充速度提升了约 1.87 倍。

#### 5. 实验数量与充分性
*   **实验规模**：论文进行了大规模的对比实验，涵盖了 5 种主流模型架构和 20 多个测试场景。
*   **消融实验**：针对衰减因子 $\lambda$ 的敏感度、计算与存储解耦的效果、动态枢轴检测的准确性进行了详尽的消融分析。
*   **客观性**：通过在不同深度的 Qwen 模型上展示“相位转换点”的自动漂移（从 12 层到 28 层），有力地证明了动态检测比固定层剪枝（FastKV）更科学、更公平。

#### 6. 主要结论与发现
*   **性能卓越**：在仅保留 10% KV 缓存的情况下，StructKV 在 LongBench 上的表现接近全上下文模型，且显著优于 FastKV 和 GemFilter。
*   **检索鲁棒性**：在 128K 长度的 RULER 测试中，StructKV 成功修复了 FastKV 在超长文本下的性能崩塌，证明了全局中心性对“休眠”关键信息的保护作用。
*   **自适应能力**：模型越深，注意力稳定的层数越靠后。StructKV 能够自动识别这一规律，无需手动调参。

#### 7. 优点（亮点）
*   **全局视野**：解决了局部显著性导致的“误删”问题，通过累积注意力识别真正的结构骨架。
*   **高度自动化**：动态枢轴检测使得该方法可以“即插即用”到不同深度的模型中。
*   **解耦策略**：灵活平衡了预填充阶段的计算精度与生成阶段的显存压力。
*   **低开销**：算法实现高效，额外引入的计算负担几乎可以忽略不计。

#### 8. 不足与局限
*   **长度验证上限**：受限于算力资源，实验最高仅验证至 128K Token，在百万级（1M+）超长上下文下的稳定性仍需进一步验证。
*   **架构覆盖**：目前主要针对标准的稠密 Transformer 架构，对于混合专家模型（MoE）或非注意力架构（如 SSM/Mamba）的适用性尚未探讨。
*   **硬件依赖**：虽然在 A800 上表现良好，但在显存带宽极度受限的边缘设备上，向量聚合操作的开销可能会被放大。
