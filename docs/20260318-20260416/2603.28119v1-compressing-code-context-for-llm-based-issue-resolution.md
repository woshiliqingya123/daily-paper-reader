## 摘要
大语言模型（LLMs）现在已经能够解决真实的 GitHub 问题。然而，当前的方法往往过度近似代码上下文，并面临两个复合问题：处理海量输入的极高成本，以及由于噪声充斥上下文窗口并干扰模型捕捉修复信号而导致的低效。现有的压缩技术无法解决这一矛盾：通用压缩器会损害代码的语义完整性，而特定于代码的工具则缺乏对代码结构和任务上下文的感知，无法保留关键的补丁要素。为此，我们提出了一个由两个组件组成的新颖框架。首先是 Oracle 引导的代码蒸馏（OCD），这是一种结合了遗传算法和增量调试（delta debugging）的上下文蒸馏算法，能够系统地将代码上下文缩减为最小充分子序列——仅保留成功修复所需的要素。我们利用这些蒸馏数据微调了 SWEzze，这是一个轻量级模型，能够在推理时学习压缩代码上下文，在过滤噪声和对抗干扰的同时保留修复要素。在 SWE-bench Verified 基准测试中，针对三种前沿 LLM 的评估结果显示，SWEzze 在不同模型上保持了约 6 倍的稳定压缩率，相对于未压缩设置减少了 51.8%-71.3% 的总 Token 预算，将问题解决率提高了 5.0%-9.2%，并且与最先进的上下文压缩基准相比，在有效性、压缩率和延迟之间实现了最佳的整体平衡。

## Abstract
Large Language Models (LLMs) are now capable of resolving real-world GitHub issues. However, current approaches overapproximate the code context and suffer from two compounding problems: the prohibitive cost of processing massive inputs, and low effectiveness as noise floods the context window and distracts the model from the bug-fixing signal. Existing compression techniques fail to resolve this tension: generic compressors compromise the semantic integrity of code, while code-specific tools lack awareness of code structure and task context to preserve essential patch ingredients. To address this, we propose a novel framework consisting of two components. First, Oracle-guided Code Distillation (OCD), a context distillation algorithm that combines genetic search and delta debugging to systematically reduce code contexts to their minimal sufficient subsequence - retaining only the ingredients required for a successful fix. We use this distilled data to fine-tune SWEzze, a lightweight model that learns to compress code context at inference time, filtering noise and combating distraction while preserving fix ingredients. Evaluated on SWE-bench Verified across three frontier LLMs, SWEzze maintains a stable compression rate of about 6 times across models, reduces the total token budget by 51.8%-71.3% relative to the uncompressed setting, improves issue resolution rates by 5.0%-9.2%, and delivers the best overall balance among effectiveness, compression ratio, and latency compared with state-of-the-art context compression baselines.

*   **现有局限**：通用压缩工具会破坏代码的语义和语法结构；而现有的代码压缩器多基于词法相似度或困惑度（Perplexity），往往会误删虽然不相似但对修复至关重要的“修复要素”（Fix Ingredients）。

### 2. 方法论：核心思想与关键技术
论文提出了一个结合“离线蒸馏”与“在线压缩”的框架，包含两个核心组件：

*   **Oracle-guided Code Distillation (OCD，Oracle 引导的代码蒸馏)**：
    *   **目标**：在训练阶段，为每个问题寻找“最小充分上下文”（Minimal Sufficient Context, MSC）。
    *   **关键技术**：
        1.  **分层表示**：将代码分解为文件、函数、块（Block）三个层级，确保压缩过程尊重语法结构。
        2.  **遗传算法 (GA)**：在指数级的组合空间中搜索能够使 LLM 成功生成正确补丁的代码子集。
        3.  **分层增量调试 (HDD)**：对 GA 找到的子集进行进一步精简，通过逐一剔除元素并验证修复效果，确保保留的每个片段都是功能性必需的。
*   **SWEzze 压缩模型**：
    *   **核心思想**：将 OCD 提取的 MSC 作为标签，训练一个轻量级的交叉编码器（Cross-Encoder）。
    *   **技术细节**：基于 `Qwen3-Reranker-0.6B` 基础模型，利用 **LoRA**（低秩自适应）进行参数高效微调。模型学习预测给定问题描述和故障位置时，哪些代码段应该被保留。
    *   **推理流程**：在实际使用时，SWEzze 对所有候选代码段进行评分，并根据预设的 Token 预算进行贪婪选择，组装成压缩后的上下文。

### 6. 主要结论与发现
*   **性能提升**：SWEzze 将问题解决率提升了 **5.0%–9.2%**，证明了“去噪”比单纯提供全量信息更有助于 LLM 修复代码。
*   **成本削减**：实现了约 **6 倍** 的稳定压缩率，总 Token 预算减少了 **51.8%–71.3%**。

### 7. 优点
*   **任务感知性强**：通过 OCD 捕获了“修复要素”而非简单的“文本相似度”，解决了传统压缩器误删关键依赖的问题。
*   **模型无关性**：虽然训练数据由 Qwen 模型生成，但在 GPT 和 DeepSeek 模型上同样表现优异，证明了 MSC 的语义通用性。
*   **结构保护**：采用分层占位符（如 `# ... N lines omitted`）替代静默删除，维持了代码的语法骨架。

### 8. 不足与局限
*   **语法破坏风险**：尽管有分层设计，但在极端压缩下仍可能产生碎片化的上下文，导致模型难以理解复杂的语义关联。
*   **区分度瓶颈**：在处理具有相同签名或高度相似逻辑的重写函数（Overridden functions）时，模型评分的精度仍有提升空间。
*   **依赖 Oracle 数据**：OCD 过程依赖于已知的正确补丁和测试套件，虽然这在训练阶段是可行的，但限制了其在缺乏历史修复数据的全新项目上的冷启动表现。
