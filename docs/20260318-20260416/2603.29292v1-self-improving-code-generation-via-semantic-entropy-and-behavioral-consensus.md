## 摘要
提升大语言模型（LLMs）的代码生成能力通常依赖于监督微调或偏好优化，这两者都需要昂贵的外部资源，例如强大的教师模型或可靠的测试单元。然而，在现实场景中，获取参考解决方案和测试判别器（test oracles）比获取问题描述和测试输入要困难得多。在本文中，我们探讨了一个具有挑战性且现实的问题：代码语言模型能否在没有更优教师模型和测试判别器的情况下实现自我改进？为了回答这个问题，我们提出了 ConSelf，这是一种基于两个核心思想的自我改进方法。首先，我们引入了代码语义熵，这是一种通过评估程序行为的功能多样性来衡量问题级不确定性的新指标，从而能够利用最具学习价值的问题构建课程。其次，我们提出了共识驱动的直接偏好优化（Con-DPO），这是一种基于偏好的微调方法，它根据行为共识对每个偏好对进行加权，从而减轻自生成监督中噪声的影响。在各种基准测试和骨干 LLM 上的实验表明，ConSelf 显著优于基线方法，验证了基于语义熵的课程构建和共识驱动优化在无需外部监督的情况下提升代码生成能力的有效性。

## Abstract
Improving the code generation capabilities of large language models (LLMs) typically relies on supervised fine-tuning or preference optimization, both of which require costly external resources such as powerful teacher models or reliable test units. However, in real-world scenarios, it is much harder to obtain reference solutions and test oracles than problem descriptions and test inputs. In this paper, we tackle a challenging yet realistic question: Can a code language model improve itself without access to a superior teacher and a test oracle? To answer this, we propose ConSelf, a self-improving approach built upon two key ideas. First, we introduce code semantic entropy, a novel metric that measures problem-level uncertainty by assessing the functional diversity of program behaviors, enabling a curriculum construction with the most learnable problems. Second, we present consensus-driven direct preference optimization (Con-DPO), a preference-based fine-tuning method that weights each preference pair by its behavioral consensus, thereby mitigating the impact of noisy self-generated supervision. Experiments on various benchmarks and backbone LLMs demonstrate that ConSelf significantly outperforms baselines, validating the effectiveness of semantic entropy-based curriculum construction and consensus-driven optimization in improving code generation without external supervision.

*   **核心问题**：如何在**没有**高性能教师模型（如 GPT-4）提供参考答案，且**没有**可靠测试判别器（Test Oracle，即标准答案输出）的情况下，让代码大语言模型（LLM）实现自我改进？
*   **研究背景**：现有的代码模型优化（如 SFT 或 DPO）高度依赖高质量的外部资源。但在现实中，获取问题描述和测试输入相对容易，而获取正确的参考代码和验证代码正确性的 Oracle 非常困难且昂贵。
*   **研究动机**：模型自生成的代码往往包含大量噪声。如果直接在这些噪声数据上训练，模型会学到错误模式。因此，需要一种方法来识别哪些问题是“可学习的”，并从不完美的自生成结果中提取稳健的改进信号。

### 2. 方法论：核心思想与关键技术
ConSelf 框架由三个阶段组成：
*   **观察引导采样（Observation-Guided Sampling）**：
    *   为了增加候选代码的多样性，模型先生成多个“观察”（如解题策略、潜在陷阱），然后基于每个观察生成多份代码。
*   **代码语义熵（Code Semantic Entropy, CSE）**：
    *   **核心思想**：通过程序执行行为的“一致性”来衡量不确定性。
    *   **技术细节**：将生成的代码在测试输入上运行，根据执行结果（输出序列）进行聚类。
    *   **公式逻辑**：对聚类分布计算香农熵（Shannon Entropy）。高熵意味着模型对该问题感到困惑（输出行为混乱）；零熵意味着模型可能已掌握或陷入单一错误。
    *   **课程筛选**：只选择熵值在特定范围 $(0, \tau)$ 内的问题构建训练课程，过滤掉不可学习的“噪声”问题。
*   **共识驱动的直接偏好优化（Con-DPO）**：
    *   **共识评分**：计算每个候选代码的输出在所有候选结果中出现的频率，作为其“行为共识分” $R(c_k)$。
    *   **加权损失函数**：在 DPO 训练中，使用共识评分作为样本权重。公式为：$\mathcal{L}_{Con-DPO} = - \mathbb{E} [R(y_w) \cdot \log \sigma(\hat{r}(y_w, y_l))]$。这使得模型更激进地学习高共识（更可靠）的偏好对，而谨慎对待低共识的样本。

*   **骨干模型**：CodeLlama-7B、DeepSeek-Coder-6.7B、Qwen2.5-Coder-7B。

    *   **Self-DPO**：在全量自生成数据上进行标准 DPO。

### 5. 实验数量与充分性
*   **实验规模**：涵盖了 3 种不同架构的骨干模型和 4 个主流基准测试，实验结果取三次运行的平均值，具有较好的统计说服力。
*   **消融实验**：分别验证了“课程筛选（CC）”和“共识加权（CW）”的有效性，证明了课程筛选对性能提升贡献最大。
*   **参数敏感性分析**：对过滤阈值 $\tau$ 进行了详细的扫参实验，揭示了数据质量与多样性之间的权衡关系。
*   **指标对比**：对比了代码语义熵与 Token 熵、负对数似然（NLL）等指标，证明了基于执行行为的指标在代码任务中更可靠。

### 6. 主要结论与发现
*   **性能提升**：ConSelf 在三个模型上分别实现了 **3.30%、2.73% 和 3.95%** 的平均相对提升。
*   **数据效率**：ConSelf 仅使用 1/7 到 1/3 的训练数据（经过筛选的高质量样本）就超过了使用全量数据的 Self-DPO。
*   **不确定性衡量**：内部置信度指标（如 NLL）在代码任务中经常失效（模型可能很自信地写出错误代码），而基于执行行为的语义熵能更准确地反映模型是否真正理解了问题。
*   **课程学习的重要性**：在无监督自改进中，“学什么”比“怎么学”更重要。

### 7. 优点
*   **现实性强**：不依赖昂贵的 Oracle 和教师模型，非常符合实际开发中缺乏标注数据的场景。
*   **行为驱动**：将代码的“可执行性”作为核心反馈信号，比纯文本层面的指标更贴合编程本质。
*   **稳健性**：通过 Con-DPO 权重机制，有效缓解了自训练中常见的“奖励黑客（Reward Hacking）”和噪声干扰问题。

### 8. 不足与局限
*   **计算开销**：需要对每个问题生成并执行多份代码以计算熵值，执行过程（尤其是大规模测试输入）会带来额外的计算负担。
*   **依赖测试输入**：虽然不需要 Oracle，但仍需要高质量的测试输入。如果测试输入无法覆盖边界情况，语义熵的准确性可能会下降。
*   **能力上限**：对于模型完全无法处理的极难问题（Pass@1 为 0 且输出完全混乱），该方法仍难以提供有效的改进路径，可能仍需外部干预。
