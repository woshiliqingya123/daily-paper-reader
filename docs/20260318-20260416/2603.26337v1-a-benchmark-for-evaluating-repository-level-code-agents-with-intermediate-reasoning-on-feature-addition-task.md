## 摘要
仓库级代码智能体在现实世界的功能添加任务中展现出巨大的潜力，这使得对其能力的可靠评估变得日益重要。然而，现有的基准测试主要基于最终测试的正确性将这些智能体视为黑盒进行评估，对于它们如何推理以及失败发生在何处提供的见解有限。为了解决这一局限性，我们推出了 RACE-bench，这是一个用于评估仓库级功能添加任务中代码智能体的推理增强型基准测试。RACE-bench 包含来自 12 个开源仓库的 528 个真实功能添加实例。每个实例都配有可执行的补丁验证以及结构化的中间推理真值（ground truth），涵盖了问题理解、文件定位、实现任务和步骤分解。基于此设计，我们引入了一个双轨评估框架，共同衡量补丁正确性和中间推理质量。我们在 RACE-bench 上评估了三个具有代表性的仓库级代码智能体。在完整基准测试中，不同智能体的解决率（Resolved Rates）在 29% 到 70% 之间。我们的推理层面分析进一步表明，虽然目前的智能体在理解高层意图方面表现良好，但在将意图转化为具体的实现步骤时，其性能会大幅下降。我们还发现，与成功案例相比，“应用成功但测试失败”的案例表现出更低的推理召回率（下降 35.7%）和更高的过度预测（增加 94.1%）。这些发现强调了通过检查推理过程的质量，在最终补丁正确性之外评估仓库级代码智能体的重要性。

## Abstract
Repository-level code agents have shown strong promise in real-world feature addition tasks, making reliable evaluation of their capabilities increasingly important. However, existing benchmarks primarily evaluate these agents as black boxes based on final test correctness, providing limited insight into how they reason and where failures arise. To address this limitation, we introduce RACE-bench, a reasoning-augmented benchmark for evaluating code agents on repository-level feature addition tasks. RACE-bench contains 528 real-world feature addition instances from 12 open-source repositories. Each instance is paired with executable patch verification and structured intermediate reasoning ground truth covering issue understanding, file localization, implementation tasks, and step decomposition. Based on this design, we introduce a dual-track evaluation framework that jointly measures patch correctness and intermediate reasoning quality. We evaluate three representative repository-level code agents on RACE-bench. On the full benchmark, Resolved Rates range from 29% to 70% across different agents. Our reasoning-level analysis further shows that while current agents perform well at understanding high-level intent, their performance degrades substantially when translating intent into concrete implementation steps. We also find that apply-success but test-fail cases exhibit lower reasoning recall (35.7% decrease) and higher over-prediction (94.1% increase) compared to successful cases. These findings highlight the importance of evaluating repository-level code agents beyond final patch correctness by examining the quality of their reasoning processes.

#### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）的发展，仓库级代码智能体（Code Agents）在自动修复 Bug 和添加新功能方面展现了巨大潜力。然而，现有的评估基准（如 SWE-bench）主要采用“黑盒”评估模式，即仅根据最终生成的补丁是否通过测试来判断成功与否。
这种评估方式存在两个主要局限：
*   **缺乏诊断能力**：无法揭示智能体在哪个环节（如需求理解、文件定位、任务规划）出错。
*   **存在偶然性**：智能体可能通过错误的推理路径偶然生成了正确的补丁。
因此，论文提出了 **RACE-bench**，旨在通过提供结构化的中间推理真值（Ground Truth），对智能体在“功能添加”任务中的推理过程进行细粒度评估。

#### 2. 论文提出的方法论
核心思想是构建一个**推理增强型**的评估框架，将开发流程分解为可量化的中间步骤。

*   **核心组件**：
    1.  **任务上下文**：包括功能需求描述、环境配置和开发者讨论提示。
    2.  **推理真值（Reasoning Ground Truth）**：涵盖四个阶段五个模块：
        *   **问题理解**：概念解释（领域术语）和目标期望（行为总结）。
        *   **文件定位**：区分必要代码文件、辅助文件和测试文件。
        *   **实现任务**：识别具体的代码实体（函数/方法）、变更类型及其目的。
        *   **步骤分解**：将实现过程抽象为最小语义步骤序列（如引入新能力、重用语义等）。
    3.  **验证模块**：提供金标准补丁（Gold Patch）和测试用例（FTP/PTP）。

*   **双轨评估框架**：
    *   **补丁轨迹**：衡量 Resolved Rate（解决率）和 Patch Apply Rate（补丁应用成功率）。
    *   **推理轨迹**：利用 **LLM-as-Judge** 结合确定性匹配，评估智能体在上述五个模块中的召回率（Recall）和过度预测率（Over-prediction）。

#### 6. 论文的主要结论与发现
*   **性能差异**：mini-SWE-Agent 表现最佳（解决率 70.08%），而 AutoCodeRover 过于保守（28.79%）。
*   **推理“瀑布式退化”**：智能体在理解高层意图方面表现优异（得分 > 9.2/10），但在将其转化为具体实现步骤时性能大幅下降（步骤召回率仅约 40%-50%）。
*   **失败特征**：失败案例通常表现为低召回率和高过度预测（冗余修改），其中步骤分解的准确性是预测补丁成功的关键指标。
*   **架构 vs 模型**：Agent 的架构设计（如工具交互的稳定性）比底层 LLM 的选择对最终性能的影响更大。
*   **推理风格**：GPT 系列模型倾向于更精准的修改（低过度预测），而 GLM 在目标对齐上稍弱。

#### 7. 优点
*   **细粒度评估**：填补了代码智能体中间推理过程评估的空白，提供了结构化的真值。
*   **真实性高**：基于真实 GitHub PR 构建，且专注于复杂的“功能添加”任务而非简单的 Bug 修复。
*   **诊断性强**：提出的双轨评估框架能有效区分“理解错误”与“执行错误”。
*   **环境可靠**：提供统一的 Docker 容器化执行环境，确保了实验的可重复性。

#### 8. 不足与局限
*   **语言局限性**：目前仅覆盖 Python 语言，尚未验证在其他编程语言上的泛化效果。
*   **真值构建偏差**：推理真值的构建部分依赖于 LLM 辅助生成，尽管经过了审计和人工抽检，仍可能存在潜在的语义偏差。
*   **Agent 暴露限制**：评估依赖于 Agent 导出的交互日志，如果 Agent 不透明或不输出中间思考过程，该基准测试的效用会受限。
*   **LLM-as-Judge 风险**：虽然研究表明 LLM 评估在 SE 领域有效，但仍存在模型偏好或评分不一致的风险。
