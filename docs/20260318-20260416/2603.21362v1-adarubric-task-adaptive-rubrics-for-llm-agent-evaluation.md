## 摘要
LLM-as-Judge 评估在智能体任务中表现不佳，因为固定的评分标准无法捕捉特定任务的核心要素：例如代码调试需要“正确性”和“错误处理”，而网页导航则需要“目标对齐”和“动作效率”。我们提出了 ADARUBRIC，通过根据任务描述动态生成特定任务的评估标准来弥补这一差距。它利用置信度加权的各维度反馈对轨迹进行逐步评分，并使用创新的维度感知过滤器（DimensionAwareFilter）筛选偏好对——这是防止高分维度掩盖特定维度失败的可证明必要条件。在 WebArena 和 ToolBench 上，ADARUBRIC 实现了与人类评估 0.79 的 Pearson 相关系数（比最佳静态基准提升 0.16），并具备部署级的可靠性（Krippendorff's $α$=0.83）。在三个基准测试中，基于 ADARUBRIC 偏好对训练的 DPO 智能体相比 Prometheus 提升了 6.8 至 8.5 个百分点的任务成功率；这些增益可迁移至 SWE-bench 代码修复（提升 4.9 个百分点），并在 5000 步时将 PPO 收敛速度提高 6.6 个百分点，且上述过程均无需任何评分标准工程。

## Abstract
LLM-as-Judge evaluation fails agent tasks because a fixed rubric cannot capture what matters for this task: code debugging demands Correctness and Error Handling; web navigation demands Goal Alignment and Action Efficiency. We present ADARUBRIC, which closes this gap by generating task-specific evaluation rubrics on the fly from task descriptions, scoring trajectories step-by-step with confidence-weighted per-dimension feedback, and filtering preference pairs with the novel DimensionAwareFilter - a provably necessary condition for preventing high-scoring dimensions from masking dimension-level failures. On WebArena and ToolBench, ADARUBRIC achieves Pearson r=0.79 human correlation (+0.16 over the best static baseline) with deployment-grade reliability (Krippendorff's $α$=0.83). DPO agents trained on ADARUBRIC preference pairs gain +6.8 to +8.5 pp task success over Prometheus across three benchmarks; gains transfer to SWE-bench code repair (+4.9 pp) and accelerate PPO convergence by +6.6 pp at 5K steps - both without any rubric engineering. #### 1. 核心问题与整体含义

**AdaRubric** 的提出基于这样一个核心洞察：评估维度应该是任务的函数，而非评估器的固定属性。它旨在通过动态生成与任务高度相关的评分标准，实现对智能体轨迹更精准、更具任务感知力的评估。

#### 2. 方法论
AdaRubric 框架包含三个主要阶段：

*   **阶段 1：自适应标准生成（Adaptive Rubric Generation）**
    根据任务描述 $T$，利用 LLM 动态生成 $N$ 个（默认 5 个）正交的评估维度。每个维度包含名称、权重以及详细的 5 分制评分准则（包含具体行为示例）。这些标准会被缓存以降低成本。
*   **阶段 2：置信度加权轨迹评估（Confidence-Weighted Evaluation）**
    评估器逐步（Step-by-step）对轨迹进行评分。对于每一步，评估器不仅给出分数 $s$，还给出置信度 $c$（反映该步骤与当前维度的相关性）。
    *   **聚合逻辑**：采用置信度加权平均（Weighted Mean），并引入时间衰减参数 $\lambda$（Recency-decay），倾向于给后续步骤（通常与目标达成更相关）更高的权重。
*   **阶段 3：维度感知过滤（Dimension-Aware Filtering）**
    引入了 **DimensionAwareFilter**。其核心逻辑是：一个合格的轨迹必须在所有关键维度上都达到阈值。这防止了“总分高但某一关键维度（如安全性或逻辑）彻底失败”的轨迹被选为正例。
