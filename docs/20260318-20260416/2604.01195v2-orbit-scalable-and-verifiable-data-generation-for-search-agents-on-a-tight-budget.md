## 摘要
搜索智能体将语言模型（LM）与网络搜索相结合，在回答复杂用户查询方面正变得至关重要。由于昂贵的人工标注或繁琐的前提条件，为涉及多步检索和推理的深度研究任务构建训练数据集仍然具有挑战性。在这项工作中，我们介绍了 ORBIT，这是一个包含 20,000 个推理密集型查询及其简短可验证答案的训练数据集，该数据集是使用一种不依赖付费 API 服务的节俭框架生成的。该模块化框架包含四个阶段：种子创建、问答对生成，以及两个验证阶段（自我验证和外部验证）。ORBIT 涵盖 15 个领域，每个训练对需要 4-5 个推理步骤，并需要通过全网进行外部搜索验证。我们使用 GRPO 算法在 ORBIT 上训练 Qwen3-4B 作为基础模型，并在维基百科问答任务上进行了评估。广泛的实验结果表明，ORBIT-4B 在 4B 参数以下的搜索智能体大语言模型（LLM）中表现优异，证明了合成数据集的实用性。我们的框架、代码和数据集均已开源并公开发布。

## Abstract
Search agents, which integrate language models (LMs) with web search, are becoming crucial for answering complex user queries. Constructing training datasets for deep research tasks, involving multi-step retrieval and reasoning, remains challenging due to expensive human annotation, or cumbersome prerequisites. In this work, we introduce ORBIT, a training dataset with 20K reasoning-intensive queries with short verifiable answers, generated using a frugal framework without relying on paid API services. The modular framework relies on four stages: seed creation, question-answer pair generation, and two stages of verification: self and external. ORBIT spans 15 domains and each training pair requires 4-5 reasoning steps, with external search verification required from the complete web. We train Qwen3-4B as the base model on ORBIT using GRPO and evaluate it on Wikipedia question answering tasks. Extensive experiment results demonstrate that ORBIT-4B achieves strong performance among sub-4B LLMs as search agents, proving the utility of synthetic datasets. Our framework, code and datasets are open-sourced and available publicly.

#### 1. 核心问题与整体含义（研究动机和背景）
随着大语言模型（LLM）的发展，**“深度搜索”（Deep Search）**成为新前沿，要求智能体能够处理复杂查询、进行多步检索和跨源推理。然而，构建此类任务的训练数据面临三大挑战：
*   **成本高昂**：人工标注复杂查询及其验证路径极其费时费力。
*   **现有数据局限**：如 NQ 和 HotpotQA 等传统数据集推理深度不足（通常仅 1-2 跳）；而一些合成数据集往往依赖昂贵的付费 API（如 GPT-4）或复杂的前置条件（如构建知识图谱）。
*   **预算限制**：研究者往往缺乏大规模调用商业搜索 API 或顶级模型 API 的资金。

**ORBIT** 的核心目标是提供一个**节俭（Frugal）且模块化**的框架，在不依赖付费 API 的情况下，生成大规模（20K）、高难度、可验证的深度搜索训练数据。

#### 2. 方法论：核心思想与关键技术
ORBIT 采用了一个自动化的四阶段框架来构建“长问题、短答案”的推理密集型数据集：
1.  **种子创建（Seed Creation）**：确定 15 个领域（如科技、法律、谜题等），利用工具生成每个领域约 100 个维基百科类别，并提取相关页面标题作为种子。
2.  **问答对生成（QA Pair Generation）**：使用带有搜索功能的 **DeepSeek-V3.1**（通过 Selenium 自动化操作网页端以规避 API 费用），根据种子生成“反向问题”——即问题包含多个事实线索，需要多步搜索才能锁定唯一的简短答案。
3.  **自我验证（Self-Verification）**：再次调用带搜索功能的 DeepSeek-V3.1，要求其验证生成的答案是否满足问题中的所有原子事实，并提供支持性的 URL 引用。
4.  **外部验证（External Verification）**：为消除模型自偏见，使用级联的 LLM 裁判（Qwen3-4B 和 GPT-oss-120b）结合爬取的网页内容进行独立验证，仅保留验证通过的样本。

**训练技术**：使用 **GRPO（群体相对策略优化）** 算法，以 Qwen3-4B 为基础模型，配合免费的 DDGS 搜索工具进行强化学习训练。

#### 3. 实验设计
*   **数据集与场景**：
    *   **单跳 QA**：Natural Questions (NQ), TriviaQA (TQA), PopQA。
    *   **多跳 QA**：HotpotQA (HQA), 2WikiMultihopQA, MuSiQue, Bamboogle, 以及极具挑战性的 **FRAMES**。
*   **Benchmark 与对比方法**：
    *   对比了参数量在 4B 以下的多种搜索智能体，包括 Search-R1-3B/4B、InfoSeeker-3B/4B、ZeroSearch、AutoRefine 等。
    *   评估指标为 **Exact Match (EM) 准确率**。

*   **算力设备**：使用了 **4 张 NVIDIA H100 GPU**。
*   **训练时长**：训练 160 个步骤，耗时约 **1-2 天**。
*   **数据生成成本**：强调“零预算”，主要通过自动化脚本利用免费的网页端大模型接口完成。

#### 5. 实验数量与充分性
*   **实验规模**：在 8 个主流维基百科 QA 任务上进行了全面测试。
*   **消融实验**：
    *   测试了不同的**数据集混合比例**（如 NQ:HotpotQA:ORBIT 的比例），发现 1:1:1 的均衡混合效果最好。
    *   测试了**搜索结果数量（Top-K）**的影响，发现 Top-5 在性能与延迟之间达到了最佳平衡。
*   **充分性评价**：实验涵盖了从简单到极难的多种场景，并进行了跨模型底座（Qwen2.5 vs Qwen3）的对比，实验设计较为客观、公平。

#### 6. 主要结论与发现
*   **ORBIT 数据集的有效性**：ORBIT-4B 在 4B 以下模型中表现最强，平均 EM 准确率比 Search-R1-4B 高出 **9.0 个百分点**。
*   **合成数据的价值**：证明了即使在紧凑预算下，高质量的合成数据也能显著提升小模型的复杂推理和工具使用能力。
*   **数据混合策略**：对于小参数模型，直接训练极难题目并非最优，混合简单（单跳）和困难（多跳）数据能提供更好的学习梯度。
*   **模型底座影响**：Qwen3-4B 作为底座在搜索任务上展现了比 Qwen2.5 更好的原生推理潜力。

#### 7. 优点
*   **低成本可扩展**：提出了一套不依赖付费 API 的生产流程，极大地降低了深度搜索研究的门槛。
*   **高质量验证**：通过自我验证和外部级联验证的双重机制，确保了合成数据的可靠性。
*   **领域广泛**：涵盖 15 个领域，且问题复杂度（平均 4-6 个推理步骤）显著高于现有数据集。
*   **完全开源**：开源了框架、20K 数据集及训练好的模型，具有很高的社区价值。

#### 8. 不足与局限
*   **模型规模限制**：由于预算原因，实验主要集中在 4B 以下的小模型，尚未在大规模模型（如 70B+）上验证 ORBIT 的增益上限。
*   **搜索工具稳定性**：使用的免费 DDGS 搜索工具在服务器繁忙时可能导致结果质量波动，影响训练稳定性。
*   **自偏见风险**：尽管引入了外部验证，但生成和初步验证仍高度依赖 DeepSeek 系列模型，可能存在潜在的分布偏差。
*   **推理延迟**：多步搜索虽然准确率高，但在实际应用中会带来较高的推理延迟。
